# BOT-LPC — бот колледжа для MAX

Бот для мессенджера **MAX** (только MAX, без Telegram): регистрация студентов, расписание, обращения с перепиской «студент ↔ сотрудник», рассылки и админ-панель. FastAPI + SQLite, запуск в Docker.

## Возможности

**Студент**
- регистрация: ФИО и код группы; профиль с возможностью правки;
- 📅 расписание своей группы (ссылка на PDF);
- 💬 обратная связь и 📄 заказ справки: выбор сотрудника, которого назначил сис-админ;
- 📋 «Мои обращения»: статусы, вся переписка, ответы сотруднику;
- уведомления в MAX об ответах и смене статуса.

**Сотрудник**
- кабинет с обращениями, назначенными ему; ответ студенту, смена статуса (в работе / завершено / отклонено);
- статистика по своим обращениям;
- 📢 рассылка — только если сис-админ выдал право.

**Superadmin** (скрытая панель: `/supersecret_admin`, в боте — кнопка «🔐 Сис-админ»)
- 👥 сотрудники: добавить по MAX ID, назначить категорию (обратная связь / справки / всё), должность, кабинет, право рассылки, удалить;
- 👥 группы: справочник с названиями, переименованием (вместе со студентами и расписаниями) и скрытием;
- 📅 расписания групп: добавить, изменить, удалить;
- 📊 статистика, 📋 все обращения;
- 📢 рассылка всем или одной группе (с предпросмотром и подтверждением). Объявление приходит с подписью «— ФИО, должность», а в журнале сохраняется, кто и когда отправил;
- ⚙️ настройки: приветствие студентов, включение/выключение приёма обращений;
- 🧪 самопроверка: состояние бота и проверка связи с MAX API.

### Веб-панель сис-админа

Те же данные, что и в боте, но редактируются мышью: `http://127.0.0.1:8080/panel`
(при webhook — `https://ваш-домен/panel`).

```bash
# в .env: задать пароль и перезапустить бота
WEB_PANEL_PASSWORD=$(python -c "import secrets;print(secrets.token_urlsafe(16))")
```

Вход: ваш MAX ID (тот же, что в `SYSADMIN_IDS`) и пароль. Пока `WEB_PANEL_PASSWORD` пуст, панель отвечает 503 и ничего не показывает.

Вкладки: обзор и статистика, обращения (карточка, переписка, смена статуса), студенты, сотрудники (ФИО, должность, кабинет, категория обращений, право рассылки), группы, расписания, рассылки (в том числе тест отправки на один ID), настройки, «Журнал и тесты».

Вкладка «Журнал и тесты» показывает хвост `LOG_FILE` с фильтром по уровню и позволяет: отправить себе тестовое сообщение, проверить связь с MAX API, записать строку в журнал. Для скриптов и внешних проверок — JSON-API `/panel/api/stats`, `/panel/api/logs`, `/panel/api/broadcasts`, а открытая диагностика `/panel/api/health` (состояние без данных).

### Команды

`/start` — меню, `/cancel` — отмена ввода, `/id` — свой MAX ID, `/supersecret_admin` — панель сис-админа.
Служебные (только сис-админ): `/logs` — хвост журнала, `/test` — самопроверка и проверка API, `/panel` — адрес панели.

## Быстрый старт (Docker)

```bash
git clone https://github.com/sftp0-c/BOT-LPC.git && cd BOT-LPC
cp .env.example .env        # впишите MAX_BOT_TOKEN
docker compose up -d --build
curl http://127.0.0.1:8080/health     # {"ok":true,"platform":"MAX","mode":"polling"}
```

На Windows без Docker запустите `start.bat`: скрипт создаст `.venv`, установит зависимости, загрузит локальный CA-сертификат для MAX и проверит соединение с API до запуска сервера.

1. Токен бота: [business.max.ru](https://business.max.ru) → Чат-боты → ваш бот → Настройки. Он хранится **только** в `.env` (файл в `.gitignore`).
2. Узнайте свой MAX ID: напишите боту `/id`, впишите число в `SYSADMIN_IDS` в `.env`, выполните `docker compose up -d`.
3. Откройте бота → в кабинете появится кнопка «🔐 Сис-админ» (панель доступна только тем, чей ID в `SYSADMIN_IDS`). Добавьте сотрудников: «👥 Сотрудники → ➕» (сотрудник узнаёт свой ID командой `/id` и должен один раз нажать «Начать» в боте).
4. Добавьте расписания групп: «📅 Расписания → ➕».

### Webhook (рекомендуется для продакшена)

По умолчанию бот работает через long polling. MAX рекомендует webhook: задайте в `.env`

```
MAX_WEBHOOK_URL=https://bot.example.com/webhook
MAX_WEBHOOK_SECRET=<openssl rand -hex 24>
```

При старте бот сам регистрирует подписку. Требования MAX: HTTPS на порту 443, валидный (не самоподписанный) сертификат. Порт контейнера привязан к `127.0.0.1:8080`, поэтому нужен обратный прокси, например Caddy:

```
bot.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Заголовок `X-Max-Bot-Api-Secret` проверяется, запросы без верного секрета получают 401. Переходя с webhook на polling, удалите подписку (`DELETE /subscriptions`) — пока она есть, long polling событий не получает.

### Сертификаты Минцифры

С 19.07.2026 API MAX работает на `platform-api2.max.ru` и требует доверия к сертификатам НУЦ Минцифры. `Dockerfile` скачивает их с gu-st.ru при сборке образа (нужен доступ к этому хосту). `start.bat` сохраняет их локально в `.certs/max-ca.pem`; также можно установить сертификаты в систему или указать свой PEM-набор в `MAX_CA_BUNDLE`. Сборка Docker без установки: `docker compose build --build-arg INSTALL_RU_CA=0`.

## Данные и резервная копия

SQLite лежит в Docker-томе `bot-lpc-data` (`/app/data/database.db`), переживает пересборку контейнера.

```bash
docker run --rm -v bot-lpc-data:/data -v "$PWD":/backup alpine tar czf /backup/bot-data.tgz -C /data .
```

## Разработка и тесты

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest
$env:DATABASE_PATH = "data/database.db"
.\.venv\Scripts\python.exe -m uvicorn bot:app --reload
```

Структура: `bot.py` — точка входа и FastAPI; `handlers/` — обработчики; `repository.py` — SQL-запросы; `database.py` — схема и доступ к SQLite; `max_api.py` — клиент MAX Bot API; `webpanel.py` — веб-панель сис-админа (`/panel`); `config.py` — настройки из `.env`; `tests/` — тесты.

Журнал пишется в консоль и в `LOG_FILE` (`logs/bot.log`, ротация 5 МБ × 4). Его читают `/logs` в боте и вкладка «Журнал и тесты» панели.

## Ограничения MAX, учтённые в коде

- не больше 2 сообщений в секунду в один диалог и 4000 символов в сообщении;
- бот не может написать пользователю, который ни разу не нажимал «Начать» (такие уведомления помечаются как недоставленные);
- в группах и каналах бот не отвечает — только личные диалоги;
- события доставляются «как минимум один раз»: long polling переотдаёт события после обрыва соединения, webhook повторяет по своей политике ретраев, а два процесса/воркера могут забрать одно событие. Бот дедуплицирует их по отпечатку события (таблица `processed_updates`), поэтому дубликаты ответов пользователю не возникают;
- отправку сообщения (`POST /messages`) бот не повторяет при обрыве соединения — это создало бы дубликат; недоставленные сообщения фиксируются в логе. Не запускайте два экземпляра бота с одной базой данных.
