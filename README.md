# BOT-LPC — бот колледжа для MAX

Бот для мессенджера **MAX** (только MAX, без Telegram): регистрация студентов, расписание, обращения с перепиской «студент ↔ сотрудник», рассылки и админ-панель. FastAPI + SQLite, запуск в Docker.

## Возможности

**Студент**
- вход с выбором, кто вы: 🎓 студент или 👔 сотрудник;
- регистрация студента: ФИО и код группы с проверкой перед сохранением — на последнем шаге бот показывает «Иванов Иван / ИС-21» и спрашивает «всё верно?», ФИО можно исправить, а группу выбрать кнопкой из уже заведённых; если подпись профиля MAX похожа на ФИО, бот предлагает её одной кнопкой; профиль с возможностью правки;
- 📅 расписание группы прямо в чате: по дням недели с временем пар, аудиторией и преподавателем, а не ссылкой на PDF. Кнопки «Сегодня», «Ближайшие занятия», «Вся неделя», «Обновить»;
- 💬 обратная связь и 📄 заказ справки: выбор сотрудника, которого назначил сис-админ;
- 📋 «Мои обращения»: кто отвечает, должность, когда пришло сообщение, статусы, вся переписка;
- 🔍 поиск по обращениям, людям и сотрудникам прямо в шапке панели — один запрос, `/panel/search`;
- уведомления в MAX об ответах и смене статуса.

**Сотрудник**
- 📬 очередь обращений: счётчики по статусам, фильтры «открытые / без ответа / к выдаче /
  завершённые» и по разделам, пометка «🔔 ждёт ответа» и «📌 ждёт вашего ответа»;
- ↪️ передача обращения другому сотруднику — с комментарием или без него. Студент остаётся автором,
  сотрудник меняется, новый получает уведомление; история сохраняет, кто и кому передал;
- 📝 внутренние заметки по обращению: видит только команда, студент - никогда (в том числе в истории);
- ⚡ шаблоны ответов: в карточке обращения — «⚡ Шаблоны», подходящие под раздел; можно отправить
  как есть или дописать своё. Шаблоны заводит сис-админ (панель → «Шаблоны»), там же видно,
  сколько раз каждый применили;
- вход по коду от сис-админа (одноразовый, со сроком действия) или по заявке, которую одобряет сис-админ;
- при регистрации спрашиваются ФИО, должность (свободный текст) и кабинет — их видят студенты;
- кабинет с обращениями, назначенными ему; в списке видно, где последнее слово за студентом; ответ студенту, смена статуса (в работе / завершено / отклонено);
- статистика по своим обращениям;
- 📢 рассылка — только если сис-админ выдал право.

**Superadmin** (скрытая панель: `/supersecret_admin`, в боте — кнопка «🔐 Сис-админ»)
- меню разделено на «де��лать сегодня» и «⚙️ Ещё» (статистика, рассылка, группы, настройки, тест и журнал) — на главном экране только нужное; переключатель вида меню: «● Сис-админ / Студент / Сотрудник» — можно работать как студент или сотрудник, выбор сохраняется и переживает перезапуск;
- ✍️ создание обращений: сис-админ может сам написать обращение сотруднику («✍️ Создать обращение» в меню) — так же, как студент, с выбором раздела и сотрудника; в подписи он будет «сис-админ»;
- 👥 просмотр расписаний: «👥 Расписания» открывает расписание любой группы в чате (не путать с «📅 Расписания (PDF)» — загрузкой файлов);
- 👤 пользователи: все, кто писал боту, с ником и ссылкой на профиль MAX, фильтры «студенты / сотрудники / заявки / без регистрации», поиск по ФИО, ID, нику, группе и должности, карточка человека. Из карточки человека можно сразу сделать его сотрудником или сис-админом (должность, отдел и категория — в форме) и удалить: либо оставив его обращения, либо вместе с ними — если у него есть открытые обращения, удаление без них запрещено; сис-админа удаляют во вкладке «Сотрудники»;
- 👔 сотрудники: добавить по MAX ID, назначить категорию (обратная связь / справки / всё), должность (свободный текст), отдел (списки сотрудников группируются по отделам), кабинет, право рассылки, удалить. Ввод ID умный: можно @ник, ссылку на профиль MAX или сразу список через запятую; должность — кнопками-подсказками или своим текстом; в списке видно, сколько обращений у сотрудника за 90 дней, сколько открытых и когда он отвечал последний раз;
- 👤 без прав: вкладка «Без прав» (и кнопка в боте) — все, кто писал боту, но ещё не сотрудник. Правой кнопкой человек становится сотрудником прямо оттуда: имя берётся из реестра, остаётся выбрать должность и категорию;
- 🗝 коды и заявки: выдать код (общий или личный по MAX ID) со сроком 1 час / 24 часа / 7 дней / 30 дней / бессрочно — срок можно поменять кнопкой под уже выданным кодом, отозвать код, рассмотреть заявку (одобрить с должностью или отклонить), видеть попытки подбора кода;
- 🔐 сис-админы: список живёт в базе (вкладка «Сотрудники»): выдать права по MAX ID, **забрать права** (последнего снять нельзя), отозванные помечены и не возвращаются перезапуском — кнопка «Вернуть» есть. Права выдаются и снимаются сразу у нескольких человек (ID через запятую), а сотрудника можно повысить до сис-админа одной кнопкой из его карточки. `SYSADMIN_IDS` в .env заводит сис-админов при старте — в первый раз и для аварийного восстановления доступа. То же самое в боте: «🔐 Сис-админы» → «Снять права» / «Выдать права»;
- 👑 владелец бота: `ROOT_IDS` в .env (по умолчанию `46010397`) — человек с максимальными правами на корневом уровне. Он видит все разделы, может удалять обращения, а его права нельзя снять ни в боте, ни в панели; в списке сис-админов он помечен как «владелец» и не попадает в список сотрудников и в их статистику.
- 👥 группы: справочник с названиями, переименованием (вместе со студентами и расписаниями) и скрытием;
- 📅 расписания групп: добавить, изменить, удалить;
- 🗑 удаление обращения: сис-админ может удалить обращение целиком (переписка и история) из карточки в боте и из веб-панели, с подтверждением, записью в журнал действий и уведомлением студента;
- 🔔 «Что сделать сегодня»: сколько обращений без ответа, заявок на роль сотрудника, невыданных документов, активных кодов и зависших диалогов, среднее время ответа и сколько обращений за сутки. Кнопка «🧹 Почистить диалоги» сбрасывает зависшие состояния, чтобы человек мог начать заново;
- 📊 статистика, 📋 все обращения;
- 📢 рассылка всем или одной группе (с предпросмотром и подтверждением). Объявление приходит с подписью «— ФИО, должность», а в журнале сохраняется, кто и когда отправил;
- ⚙️ настройки: приветствие студентов, включение/выключение приёма обращений;
- 🧪 самопроверка: состояние бота и проверка связи с MAX API.

### Веб-панель сис-админа

Оформление: боковое меню с иконками (на телефоне превращается в верхнюю ленту), тёмная тема
включается системой автоматически, печать страницы без меню.

Те же данные, что и в боте, но редактируются мышью: `http://127.0.0.1:8080/panel`
(при webhook — `https://ваш-домен/panel`).

```bash
# в .env: задать пароль и перезапустить бота
WEB_PANEL_PASSWORD=$(python -c "import secrets;print(secrets.token_urlsafe(16))")
```

Вход: ваш MAX ID (тот же, что в `SYSADMIN_IDS`) и пароль. Пока `WEB_PANEL_PASSWORD` пуст, панель отвечает 503 и ничего не показывает.

Вкладки: обзор и статистика, **аналитика** (диаграммы: обращения по дням, статусы, разделы, нагрузка на сотрудников, скорость ответа, студенты по группам — чистый SVG, без внешних библиотек и без JavaScript), обращения (фильтры по статусу, разделу и «только ждут ответа») (карточка с перепиской, историей и быстрым ответом), пользователи (реестр всех, кто писал боту, с поиском, фильтрами, ссылками на профиль MAX и выгрузкой в CSV — `/panel/people.csv`; в карточке можно сразу сделать человека сотрудником или сис-админом), «Без прав» (кто писал боту, но ещё не сотрудник — выдача прав в один клик), студенты, сотрудники (ФИО, должность, отдел, кабинет, категория обращений, право рассылки, поиск, загрузка за 90 дней, добавление сразу нескольких, повышение до сис-админа), коды и заявки, **шаблоны ответов**, **страница сотрудника** (нагрузка, скорость ответа, последние
обращения - всё на одном экране), **выгрузка обращений в CSV** (`/panel/tickets.csv`, с теми же
фильтрами, что на странице), группы, расписания, рассылки (в том числе тест отправки на один ID), настройки, «Журнал и тесты».

Вкладка «Журнал и тесты» показывает хвост `LOG_FILE` с фильтром по уровню и позволяет: отправить себе тестовое сообщение, проверить связь с MAX API, записать строку в журнал. Для скриптов и внешних проверок — JSON-API `/panel/api/stats`, `/panel/api/people`, `/panel/api/requests`, `/panel/api/logs`, `/panel/api/broadcasts`, а открытая диагностика `/panel/api/health` (состояние без данных).

### Вход сотрудника без сис-админа

Сотрудник может зарегистрироваться сам — тремя способами:

1. **Код.** Сис-админ выдаёт код: кнопка «🗝 Коды и заявки → 🎟 Новый код» (общий) или «✉️ Пригласить по ID» (только одному MAX ID). Код одноразовый, срок действия — `STAFF_CODE_TTL_HOURS` (по умолчанию 24 ч), не более `STAFF_CODE_ATTEMPTS` попыток в час с одного аккаунта; о превышении сис-админы получают уведомление.
2. **Заявка.** Без кода сотрудник жмёт «📥 Подать заявку» и пишет ФИО, должность, кабинет и комментарий — заявка приходит сис-админам, одобрение создаёт сотрудника с этой должностью.
3. **Вручную.** Сис-админ добавляет сотрудника по MAX ID или прямо из карточки человека в панели.

Общие настройки входа — в `.env`:

```
STAFF_CODE_TTL_HOURS=24        # срок действия кода сотрудника
STAFF_CODE_ATTEMPTS=5          # попыток ввода кода в час с одного MAX ID
MAX_PROFILE_LINK=https://max.ru/{username}   # шаблон ссылки на профиль MAX
```

### Вкладка «База данных»

Управление базой прямо из панели — без остановки бота и без команд в консоли:

- **состояние**: путь и размер файла (с журналом WAL), версия SQLite, режим журнала, число страниц и сколько места можно освободить, `PRAGMA integrity_check` («база цела» / предупреждение), число строк в каждой таблице;
- **обслуживание**: сжатие `VACUUM`, слияние журнала `WAL` (нужно, если копируете файл вручную), чистка только служебных таблиц — отпечатков обработанных событий, попыток ввода кода и зависших состояний диалогов, с выбором срока (обращения, сообщения, сотрудники и реестр пользователей чистка не трогает);
- **резервные копии**: создать копию (согласованный снимок работающей базы через `VACUUM INTO`), скачать текущую базу или любую копию, восстановить базу из копии и удалить копию. Перед восстановлением бот сам делает страховочную копию, а перед восстановлением проверяет файл на целостность и на то, что это база бота. Хранится последние `BACKUP_KEEP` копий, папка — `BACKUP_DIR` (по умолчанию `backups` рядом с базой).

Все действия требуют входа в панель и CSRF-токена, необратимые спрашивают подтверждение.

**Проверка схемы и починка.** Панель и бот сверяют базу со схемой в коде. Если таблица удалена вручную (или потеряна колонка), страницы не падают с 500, а показывают, чего не хватает, и кнопку «🔧 Восстановить схему»: она создаёт недостающие таблицы, индексы и колонки, не трогая остальные данные. То же происходит автоматически при перезапуске бота. Удалённые данные этим не вернуть — для этого резервные копии выше. Состояние схемы видно и в `/health` (`missing_schema`), и в `/panel/api/health`.

```
BACKUP_DIR=                       # пусто — папка backups рядом с файлом базы
BACKUP_KEEP=10                    # сколько последних копий хранить
```

### Если бот перестал работать

1. `/panel` → вкладка «База данных» → посмотрите строку «Схема» и «Проверка целостности».
2. Если схема неполна — «🔧 Восстановить схему». Данные удалённых таблиц придётся завести заново.
3. Если база повреждена — восстановитесь из резервной копии (кнопка «♻️ Восстановить») и перезапустите бота.
4. Если панель недоступна совсем — перезапустите бота: при старте `init_db()` создаёт недостающие таблицы, а строка с причиной ошибки есть в журнале (`/panel` → «Журнал и тесты» или `/logs` в боте).

### Расписание: не ссылка, а разобранный PDF

Ссылку на PDF расписания задаёт сис-админ (вкладка «Расписания»). Бот скачивает
файл, разбирает его в занятия и хранит их в таблице `lessons`, поэтому студент
видит расписание текстом в чате:

```
📚 Расписание группы ИС-21
Неделя с 21.09.2026

📅 Понедельник 21.09
  1 урок · 🕐 08:00–08:45 · Математика | (лекция)
     ауд. 204 · Иванова А. А.
  3 урок · 🕐 09:50–10:35 · Физика | (лаб)
     ауд. 217 · Петров П. П.
```

Как это работает:

- **Кэш.** Разбор хранится в базе; повторное открытие расписания не обращается к
  сайту. Через `SCHEDULE_CACHE_HOURS` (по умолчанию 12) файл скачивается заново —
  если на сервере выложили новую версию, занятия обновятся сами, а подписчики
  получат уведомление с ближайшими парами. Скачанные PDF лежат в папке `schedules`
  рядом с базой (держится `SCHEDULE_CACHE_FILES` файлов).
- **Что понимает разбор.** Заголовок «День - Понедельник, 28.09.2026», таблица с
  кодами групп в шапке, ячейка вида «предмет\n(вид занятия)\nпреподаватель» и
  колонка «ауд.». Коды групп распознаются и как «24-21(2С)», и как «ИС-21».
  Таблицы ищутся сначала по рамкам, а если их нет — по колонкам пробелов.
- **Время пар.** Сами PDF времени не содержат — оно подставляется по номеру пары
  из звонков. Звонки правятся во вкладке «Расписания» (без изменения кода) и
  отдельно для одной пары в карточке группы. Несоответствие вёрстке видно сразу:
  панель показывает счётчик пар и причину неудачи («не нашлось занятий группы …»,
  «не скачался PDF: …»), а студенту в этом случае показывается ссылка как раньше.

  Номер в PDF — это **урок**, а не пара: в паре уроков два, поэтому время
  подставляется по номеру урока. В боте это видно прямо в строке: `2 урок · 🕐
  08:50–09:35`. Звонки по умолчанию:

  | Урок | Время | Пара |
  |------|-------|------|
  | 1 | 08:00–08:45 | 1 пара, 1 урок |
  | 2 | 08:50–09:35 | 1 пара, 2 урок |
  | 3 | 09:50–10:35 | 2 пара, 1 урок |
  | 4 | 10:55–11:40 | 2 пара, 2 урок |
  | 5 | 12:00–12:45 | 3 пара, 1 урок |
  | 6 | 13:05–13:50 | 3 пара, 2 урок |
  | 7 | 14:00–14:45 | 4 пара, 1 урок |
  | 8 | 14:50–15:35 | 4 пара, 2 урок |
  | 9 | 15:45–17:15 | 5 пара (один урок) |
  | 10 | 17:25–18:55 | 6 пара (один урок) |
  | 11 | 19:00–20:30 | 7 пара (один урок) |

  Редактор звонков во вкладке «Расписания» пронумерован так же, как бот. Запись
  может быть и по парам (`{"1": [["08:00","08:45"],["08:50","09:35"]]}`) — она
  развернётся в номера уроков подряд. Изменение сразу пересчитывает время у уже
  разобранных занятий, перечитывать PDF не нужно.
- **Сверить заранее.** Кнопка «🔍 Разобрать» проверяет одну группу, «🔄 Обновить
  все» — все сразу; в таблице видно, какие группы нашлись в самом PDF.

```
SCHEDULE_CACHE_HOURS=12    # через сколько часов PDF скачивается заново
SCHEDULE_CACHE_FILES=20    # сколько скачанных PDF держать на диске
```

### Импорт с сайта колледжа

Колледж выкладывает семь постоянных PDF (`23-29-24-25.pdf`, `24-26-25-20.pdf` и
остальные), а внутри файла группы идут колонками. Раньше их надо было заводить
вручную по одной. Теперь есть кнопка:

- **Бот:** «Расписания → ⬇️ Импорт с сайта» — бот скачает файлы, заведёт все группы
  и сразу разложит их расписания, отчёт придёт в личные сообщения.
- **Панель:** «Расписания → Импорт и фоны колледжа». Поле принимает и ссылку на
  страницу, и список прямых PDF (по одной в строке, можно вставлять кусками), и
  любую смесь. По умолчанию там страница
  `https://collegelan.ru/studentam/raspisanie-zanyatiy.php`.

Один сломанный или не относящийся к группам файл («График консультаций
преподавателей») не мешает остальным — он попадает в список проблем. Дальше PDF
перечитываются по обычному правилу кэша: колледж обновил файл — расписание и
подписчики получили новое.

**Сис-админ смотрит расписание так же, как студент.** В меню «Расписания» у
каждой группы есть кнопка «👀»: одно нажатие — неделя разобранного расписания,
рядом переключение на сегодня и ближайшие пары. В карточке группы (нажатие на
название) та же кнопка «👀 Открыть расписание», рядом — правка ссылки и удаление.
Карточка сразу показывает, разобран файл и сколько колонок найдено, поэтому
понятно, что именно увидит студент. Кнопки подписки у сис-админа нет: он и так
видит все расписания. Групп больше 25, поэтому список листается по 15 на
страницу — ни одна группа не прячется за обрезкой.

### Группы: один справочник вместо написаний

Код группы приводится к одному виду (`utils.group_code`) — и при импорте, и при
регистрации, и при поиске расписания:

| Написал | Стало |
|---------|-------|
| `24-23 (П)` | `24-23П` |
| `24 23 п` | `24-23П` |
| `2423П` | `24-23П` |
| `24-21(2С)` | `24-21-2С` |

Дальше:

- **Похожее, но не то** (`24-23` вместо `24-23П`) — бот не создаёт новую группу, а
  показывает кнопки с похожими и ждёт выбора.
- **Совсем новая группа** — заводится автоматически, сис-админы получают
  уведомление: скорее всего, кто-то ещё не записан.
- **Таблица `group_aliases`** хранит варианты написания, которые не сводятся
  правилом (например `ИС21` → `ИС-21`).
- **Поиск по буквам** не зависит от раскладки: `P` и `П` — одна и та же группа.

### Подписи кнопок: MAX рисует их в одну строку

Кнопка в MAX помещается в одну строку, и клиент обрезает подпись многоточием
(«Должность изме…»). Поэтому:

- `max_api.short_label()` держит подпись короче обрезки (`BUTTON_TEXT = 24`)
  и режет по границе слова, а не по символу;
- в кнопку влезает только имя человека: должность и отдел перечислены текстом
  над списком (`staff_roster` в боте, `staff_roster_text` в панели) - их видно
  целиком, и «Петрова Мария Сергее…» не путается ни с кем;
- у списка обращений в кнопке остаётся номер, статус и короткая пометка
  («№12 · В работе · 🔔 ждёт»), раздел виден в карточке;
- подменю «Обратная связь» сначала показывает должность, затем человека этой
  должности - так «Зам УРП» и «Директор» не превращаются в «Зам…».

Тесты `tests/test_button_labels.py` проверяют и исходники, и живой проход по
экранам: длиннее `BUTTON_TEXT` подпись больше не появится нигде.

### Панель на телефоне

Панель рассчитана и на компьютер, и на Android: при ширине до 1000 px боковое
меню превращается в одну прокручиваемую строку (а не в пятнадцать плиток во
весь экран), рабочее место с обращениями становится одной колонкой, широкие
таблицы прокручиваются внутри карточки и не растягивают страницу. При ширине до
640 px кнопки и пункты меню вырастают до 44 px (палец, а не курсор), поля ввода
имеют шрифт 16 px (иначе телефон зумит страницу), подписи таблиц становятся
плотнее, а второстепенные строки шапки скрываются.

### Нижнее меню: это команды, а не кнопки

MAX не показывает боту нижние кнопки под полем ввода: по документации бот
умеет присылать только inline-кнопки, а нижнее меню чата собирается из
команд бота (`PATCH /me/commands`). Поэтому меню сделано командами — они
работают и руками, и кнопкой меню рядом с именем бота:

| Команда | Что делает |
|---------|------------|
| `/menu` | главное меню |
| `/schedule` | расписание: моя группа, неделя, сегодня |
| `/today` | пары на сегодня |
| `/tickets` | мои обращения |
| `/new_request` | новое обращение |
| `/profile` | профиль и группа |
| `/queue` | очередь обращений (сотрудникам) |
| `/stats` | статистика (сотрудникам) |
| `/help` | что умеет бот |
| `/admin` | кабинет сис-админа (только сис-админам) |

Команды регистрируются при старте бота; сис-админ может обновить их кнопкой
«📱 Обновить нижнее меню» в меню «Расписания». Команда ведёт ровно туда же,
куда соответствующая кнопка, и закрывается правами: студенту `/queue`
показывает его меню, а не чужую очередь.

Инлайн-кнопки остались в списках и карточках — они относятся к конкретному
экрану. Предел клавиатуры MAX — 30 строк в одном сообщении, длинные списки
режутся автоматически, а перебор групп листается постранично.
### Команды


`/start` — меню, `/cancel` — отмена ввода, `/id` — свой MAX ID, `/supersecret_admin` — панель сис-админа.
Служебные (только сис-админ): `/logs` — хвост журнала, `/test` — самопроверка и проверка API, `/panel` — адрес панели.

### Обращения: рабочее место вместо страницы карточки

Вкладка «Обращения» — это очередь слева и выбранное обращение справа, на одном
экране. Отдельной страницы карточки больше нет: старые ссылки из отчётов
(`/panel/tickets/12`) ведут в рабочее место с открытым обращением.

В карточке редактируется всё, что вообще может быть у обращения: текст, категория,
тема, ответственный, статус, **кабинет выдачи** и срок готовности. Пустое поле не
затирает старое значение, а каждое изменение попадает в историю — видно, кто и
что поменял.

- **Кнопка «✅ Справка готова»** — одним нажатием ставит статус «готово», пишет
  студенту «заберите в кабинете 115» и отправляет уведомление. Кабинет по
  умолчанию 115, но если в обращении проставлен другой (исключение), уважается он.
- **Массовые действия** — отметили несколько обращений галочкой слева и
  назначили сотрудника, сменили статус, поставили кабинет или убрали в архив.
- **Архив вместо удаления.** «🗄 В архив» ничего не стирает: обращение уходит из
  очереди, но переписка и история остаются, вернуть его можно одним действием.
  Студенту уходит уведомление. Жёсткое удаление осталось в боте у сис-админа
  для неисправимых случаев.
- **Создание из панели** — «➕ Создать обращение»: MAX ID, ФИО, группа, категория,
  исполнитель, текст. Удобно для заявок, пришедших не через бота.
- **Кто видит чужие обращения** — в правой колонке галочка рядом с сотрудником.
  Без неё сотрудник видит только свои обращения (и в панели, и в очереди бота);
  сис-админы видят всё независимо от настроек.

### Обращения в боте: черновик и короткий путь

- **Меню студента** теперь содержит конкретные обращения: «📄 Справки»,
  «🎓 Учёба», «💰 Стипендия», «💬 Другое» — вместо одного «нового обращения»
  с двумя шагами выбора.
- **Черновик.** Первое сообщение не создаёт обращение: текст сохраняется, и
  снизу появляются кнопки «✉️ Отправить обращение», «🗑 Очистить черновик» и
  «↩️ В меню». Можно написать несколько сообщений подряд — они склеятся в один
  текст, — и отмен��ть всё одним нажатием, не создавая обращения.
- **«✅ Готово (115)»** в карточке обращения у сотрудника: закрывает обращение и
  пишет студенту, где забрать документ.
- **Файлы к обращению.** После создания обращения есть кнопка «📎 Прикрепить
  файл»: прикреплённый файл попадает в переписку, сотрудник получает уведомление
  и открывает файл в панели. Файлы лежат в папке `attachments` рядом с базой
  (тот же том, что и бот), одноимённые не затирают друг друга: к имени
  добавляется короткий хеш содержимого. Принимаются фото, PDF и документы Word
  и Excel до 20 МБ, всё остальное отклоняется с понятной причиной.
- **Расписание преподавателя** — кнопка «👨‍🏫 Преподаватель» в меню или команда
  `/teacher`: достаточно части фамилии, бот покажет неделю преподавателя с
  группами и аудиториями.

### Бот сам следит за расписанием колледжа

Отдельная фоновая проверка ходит на страницу с PDF, скачивает каждый файл один
раз за круг и сверяет его отпечаток с сохранённым:

- файл не изменился — не делается ничего, ни разбора, ни писем;
- файл изменился и занятия действительно другие — подписчикам групп приходит
  сообщение с ближайшими парами;
- файл перезаписали тем же содержимым — тишина, письма не летят впустую;
- недоступный или нечитаемый PDF не мешает остальным, сис-админ получает одно
  сообщение с причинами (с кулдауном 6 часов).

Интервал — 12 часов (константа `WATCH_INTERVAL_HOURS` в `schedule_watch.py`).
Уведомления получают только те, кто подписался на свою группу кнопкой
«🔔 Подписаться на обновления».

### Неделя расписания берётся из самого PDF

Колледж кладёт в шапку каждой страницы дату («День — Понедельник, 28.09.2026»),
поэтому неделю не нужно угадывать: `timetable.week_of_pages()` находит самую
раннюю дату и запоминает понедельник этой недели в `GroupSchedule.week`. В шапке
расписания показывается именно эта неделя, а не текущая - иначе на стыке недель
студент сверялся с неверной датой. Дополнительно:

- день, на который пришёлся сегодняшний, помечен «• сегодня»;
- если файл старше текущей недели, бот прямо пишет, что колледж ещё не выложил
  свежее расписание, и сколько дней прошло, - вместо тихого показа устаревших пар;
- если в PDF даты нет (старый или другой формат файла), поведение прежнее:
  неделя считается от текущего понедельника.

### Справочник колледжа и частые вопросы

Всё, что бот рассказывает о колледже, лежит в модуле `college.py` и переписано со
страниц официального сайта [collegelan.ru](https://collegelan.ru/): адрес
(628672, ХМАО-Югры, г. Лангепас, ул. Ленина, 52), телефоны приёмной директора
(2-26-50), учебной части (2-71-33), бухгалтерии (2-26-34), факс и приёмная
комиссия, почта, режим работы и часы приёма документов. Студент видит это в
профиле одной строкой и целиком по кнопке «🏫 Контакты колледжа». Любое поле
сис-админ переопределяет в панели («Колледж»); пустое поле возвращает значение с
сайта, а не затирает его.

FAQ-бот отвечает на частые вопросы сам: человек пишет вопрос обычным текстом, бот
ищет ответ по ключевым словам с нормализацией («стипендию» = «стипендия»,
регистр, «ё/е», пунктуация). Правила жёсткие:

- при равном балле у двух разных вопросов бот не отвечает - лучше промолчать,
  чем ответить не на тот вопрос;
- если ответа нет, бот не выдумывает его, а предлагает написать сотруднику;
- ответы и вопросы правятся в панели («Колледж» → «Частые вопросы»), каждый
  вопрос можно выключить, не удаляя; ответы на вопросы ботом отключаются одним
  переключателем.

В таблицу `faq` при каждом старте бота заливается черновик из 17 вопросов с сайта
(`college.DEFAULT_FAQ`). Заливка идемпотентная: новые вопросы добавляются, правки
сис-админа не затираются. Суммы стипендии на сайте не опубликованы (только
ссылки на документы) - в ответе так и сказано, цифры не выдуманы.

### Приглашение по ссылке с одноразовым кодом

Раньше код сотрудника надо было передать в руки и объяснить, куда его вводить.
Теперь у каждого активного кода в панели («Доступы и заявки») есть ссылка
`/join/<код>` — её можно отправить в мессенджере или показать на экране:

- страница приглашения открывается **без входа в панель** и показывает сам код,
  срок его действия и кнопку «Открыть бота в MAX»;
- в боте код принимает команда `/join КОД` (работает и `/join:КОД`);
- код одноразовый и с ограничением по сроку: погашение проверяется и снимается
  одной атомарной операцией, поэтому два человека с одной ссылкой не пройдут;
- если код уже использован или истёк, страница прямо говорит об этом, а не
  предлагает снова его ввести.

Адрес бота для кнопки берётся из `MAX_PROFILE_LINK` (по умолчанию
`https://max.ru/{username}`), а имя `{username}` бот узнаёт о себе при старте и
запоминает — вписывать руками ничего не нужно. Чтобы ссылки были абсолютными
(например, для телефона в другой сети), задайте в `.env` `PUBLIC_URL`; без него
ссылка получается относительной и открывается внутри сети, где видна панель.

### Демо-стенд: щёлкать можно, портить нельзя

Режим показа, в котором бот отвечает на все экраны, но не меняет данные. Нужен,
чтобы показать бота директору, принять гостей или проверить новую функцию на
живой базе:

- просмотр работает как обычно: расписание, профиль, списки, обращения, справка;
- создание обращений, смена статусов, рассылки, архивирование, выдача прав и
  отправка файлов честно отвечают «в демо-режиме это не выполняется» и не трогают
  базу;
- сценарии ввода (регистрация, поиск преподавателя, новый черновик) не
  запускаются — вместо них экран стенда;
- единственная запись в базу — отметка «демо» в журнале действий.

Включается из меню сис-админа («🎬 Демо-стенд» → «Включить»), переключателем в
панели («Настройки» → «Демо-стенд») и командой `/demo`. Выход: кнопка «↩️ Выйти
из демо», кнопка «🏠 Меню» или команда `/demo_off`. Перехват стоит в `bot.on_callback`
и в пяти опасных местах обработчика обращений, поэтому держится на всех экранах,
а не на одной кнопке.

### Согласие на обработку данных

При первой регистрации бот просит согласие и только потом сохраняет ФИО и группу.
Текст согласия правится в панели («Настройки» → «Согласие на обработку данных»),
дата и редакция текста хранятся рядом с профилем (`users.consent_at`,
`users.consent_version`). Уже зарегистрированным людям согласие не докучает:
оно спрашивается один раз, при регистрации, а список тех, кто его не давал, виден
в панели («Студенты» → фильтр «только без согласия»).

### Пробелы в данных: подсказка на главной панели

Карточка «Пробелы в данных» на главной показывает, что мешает боту работать
полноценно: сотрудники без должности или роли (подменю «Обратная связь» и адресные
обращения не работают), студенты без группы или ФИО, группы без расписания и люди
без согласия. Каждая строка — ссылка на то, где это дополняется.

### Сотрудник в отпуске

В карточке сотрудника есть отметка «Отпуск до» (панель → «Сотрудники» → карточка).
Пока сотрудник в отпуске, новые обращения к нему уходят заместителю — сотруднику с
той же должностью, а если такого нет, с тем же разделом обращений. Студенту бот
прямо говорит, что сотрудник в отпуске и кто ответит; если заместитель не назначен,
он честно предупреждает, что обращение подождёт. Без заместителя обращение
остаётся у отсутствующего, а не теряется.

### Что можно добавить позже

- **Опросы для колледжа.** Система спрашивает, студенты отвечают кнопками,
  ответы собираются в панели с разбивкой по группам. Механика частично готова:
  групповые массовые действия и аналитика по категориям позволяют разослать
  вопрос и разобрать ответы вручную; отдельный конструктор опроса — следующий
  шаг.
- **Печатная форма обращения** на одну страницу для архива и подписи, выгрузка
  за период по фильтру (CSV уже есть).
- **Статусы с дедлайном и эскалация** — если понадобится контроль сроков.
- **Доступ по категориям.** Сейчас сотрудник видит либо все обращения, либо
  только свои (галочка в рабочем месте панели). Тоньше - выдать доступ по
  разделам: секретарь видит справки, бухгалтерия - стипендию и выплаты.
  Технически это ещё одна колонка в `admins` и фильтр в `repo.admin_tickets`.
- **Аварийный режим.** Если бот или панель лежат во время приёмной кампании,
  нужен запасной путь: заранее выгруженный список групп и расписаний на
  телефон, чтобы секретарь мог ответить студенту без сервера. Смысл есть
  только вместе с регулярной выгрузкой, поэтому пока записано идеей.
- **Приглашение по ссылке с одноразовым кодом.** Сейчас сотрудник заводится
  из бота сис-админом или по коду доступа. Ссылка вида `bot/join/<код>`,
  которая сгорает после первого входа, снимает лишний шаг и не даёт коду
  утечь в чаты.

На Windows без Docker запустите `start.bat`: скрипт создаст `.venv`, установит зависимости, загрузит локальный CA-сертификат для MAX и проверит соединение с API до запуска сервера.

Для Docker на Windows нужны **Docker Desktop и WSL2**. Если WSL2 не установлен, Docker Desktop не запустит движок («500 Internal Server Error» вместо `docker info`); установить:

```powershell
wsl --install --no-distribution   # затем перезагрузка
winget install -Eid Docker.DockerDesktop
```

1. Токен бота: [business.max.ru](https://business.max.ru) → Чат-боты → ваш бот → Настройки. Он хранится **только** в `.env` (файл в `.gitignore`).
2. Узнайте свой MAX ID: напишите боту `/id`, впишите число в `SYSADMIN_IDS` в `.env`, выполните `docker compose up -d`.
3. Откройте бота → в кабинете появится кнопка «🔐 Сис-админ» (панель доступна только тем, чей ID в `SYSADMIN_IDS`). Добавьте сотрудников: «👥 Сотрудники → ➕» (сотрудник узнаёт свой ID командой `/id` и должен один раз нажать «Начать» в боте).
4. Добавьте расписания групп: «📅 Расписания → ➕».

### Управление контейнером

```powershell
docker compose up -d --build   # собрать образ и запустить (после перезагрузки ПК)
docker compose ps              # статус: должно быть Up ... (healthy)
docker compose logs -f         # журнал
docker compose restart         # перезапустить
docker compose down            # остановить (данные в томе остаются)
docker compose up -d           # снова запустить
```

`restart: unless-stopped` — после перезагрузки компьютера бот поднимается сам, если
Docker Desktop запущен вместе с системой. Через 30 секунд после старта включается
healthcheck: он открывает `/health` и ждёт ответа, поэтому в `docker compose ps`
состояние должно быть `healthy`.

### Панель сис-админа: с этого компьютера и с телефона

- на этом же компьютере: `http://127.0.0.1:8080/panel`;
- с телефона или другого ноутбука в той же домашней сети: `http://<IP-компьютера>:8080/panel`
  (IP виден в `ipconfig`, сейчас 192.168.0.102). Порт привязан к `0.0.0.0`, поэтому
  панель видна в сети; вход защищён паролем `WEB_PANEL_PASSWORD` и CSRF-токеном форм.
  Если страница не открывается — разрешите порт 8080 в брандмауэре Windows
  (или в антивирусе) для частных сетей.

В интернет панель не выставляется: наружу пробрасывать нужно только сам обратный
прокси, и то для webhook (см. ниже).

### Где лежат данные

Всё изменяемое лежит в томе `bot-lpc-data`, внутри контейнера это `/app/data/`:

### Если бот уже работал без Docker

Старую базу из `data/database.db` можно перенести в том. Контейнер на время
останавливаем — тогда копия гарантированно согласована (в базе может быть
незакрытая WAL-транзакция):

```powershell
docker compose stop
Copy-Item data\database.db data\snapshot.db
docker run --rm -v bot-lpc-data:/data -v "${PWD}:/src:ro" bot-lpc:latest `
    python -c "import shutil;shutil.copy('/src/data/snapshot.db','/data/database.db')"
docker compose start
Remove-Item data\snapshot.db
```

> Запускайте бота **либо** в контейнере, **либо** через `start.bat`, но не оба
> одновременно: у локального запуска своя база в `data/`, и события MAX будут
> обрабатывать оба процесса.

### Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `docker info` → 500 | не установлен WSL2 или нужна перезагрузка после установки |
| `docker compose ps` → `Exit 1` | смотрите последние строки `docker compose logs` |
| `/health` → `"ok": false` | в базе не хватает таблиц: вкладка «База данных» → «Восстановить схему» |

### Webhook (если появится домен)

По умолчанию бот работает через long polling, и для вашей задачи (одна машина, без
домена) этого достаточно: MAX отдаёт события сам, входящий порт не нужен.

Если домен появится, задайте в `.env`:

```
MAX_WEBHOOK_URL=https://bot.example.com/webhook
MAX_WEBHOOK_SECRET=<openssl rand -hex 24>
```

При старте бот сам регистрирует подписку. Требования MAX: HTTPS на порту 443, валидный
(не самоподписанный) сертификат. Порт контейнера слушает `0.0.0.0:8080`, поэтому
обратный прокси на этой же машине подключается к `127.0.0.1:8080`, а во внешнюю сеть
пробрасывать порт не нужно:

```
bot.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Заголовок `X-Max-Bot-Api-Secret` проверяется, запросы без верного секрета получают 401. Переходя с webhook на polling, удалите подписку (`DELETE /subscriptions`) — пока она есть, long polling событий не получает.

### Сертификаты Минцифры

С 19.07.2026 API MAX работает на `platform-api2.max.ru` и требует доверия к сертификатам НУЦ Минцифры. `Dockerfile` скачивает их с gu-st.ru при сборке образа (нужен доступ к этому хосту). `start.bat` сохраняет их локально в `.certs/max-ca.pem`; также можно установить сертификаты в систему или указать свой PEM-набор в `MAX_CA_BUNDLE`. Сборка Docker без установки: `docker compose build --build-arg INSTALL_RU_CA=0`.

```powershell

.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Структура: `bot.py` — точка входа и FastAPI; `handlers/` — обработчики (в том числе `faq.py` — частые вопросы, `demo.py` — демо-стенд); `college.py` — справочник колледжа; `timetable.py` — разбор расписания и его неделя; `repository.py` — SQL-запросы; `database.py` — схема и доступ к SQLite; `max_api.py` — клиент MAX Bot API; `webpanel.py` — веб-панель сис-админа (`/panel`); `config.py` — настройки из `.env`; `tests/` — тесты.

Журнал пишется в консоль и в `LOG_FILE` (`logs/bot.log`, ротация 5 МБ × 4). Его читают `/logs` в боте и вкладка «Журнал и тесты» панели.

## Ограничения MAX, учтённые в коде

- не больше 2 сообщений в секунду в один диалог и 4000 символов в сообщении;
- бот не может написать пользователю, который ни разу не нажимал «Начать» (такие уведомления помечаются как недоставленные);
- в группах и каналах бот не отвечает — только личные диалоги;
- события доставляются «как минимум один раз»: long polling переотдаёт события после обрыва соединения, webhook повторяет по своей политике ретраев, а два процесса/воркера могут забрать одно событие. Бот дедуплицирует их по отпечатку события (таблица `processed_updates`), поэтому дубликаты ответов пользователю не возникают;
- отправку сообщения (`POST /messages`) бот не повторяет при обрыве соединения — это создало бы дубликат; недоставленные сообщения фиксируются в логе. Не запускайте два экземпляра бота с одной базой данных.
