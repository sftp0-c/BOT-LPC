# Состояние проекта «Навигатор ЛПК»

Документ отвечает на три вопроса: что сделано, что не сделано и почему, как
всё проверить. Пишется по делу, без истории правок — историю видно в git.

Дата: 30 сентября 2026. Версия бота: 1.3.0 (в 1.3.0 вошёл мост; включается
настройками и по умолчанию выключен).

---

## 1. Что работает

### Бот для студентов
* Регистрация с подтверждением, профиль, группы.
* Расписание: разбор PDF, подписки, актуальность 12 часов.
* Частые вопросы, справки, бухгалтерия, обращения к сотрудникам.
* Обратная связь **без темы обращения** — намеренное решение, оно закреплено
  проверкой `test_feedback_ticket_has_no_topic`. Темы усложняли путь и ничего
  не давали.
* Вход сотрудников по приглашению: на экране ФИО, должность, кабинет, раздел.

### Панель сис-админа (`/panel`)
* Кабинет 115 — только под справки.
* Права сис-админа на все обращения, архив, восстановление.
* Ответ «за сотрудника»: автором ответа и смены статуса становится сотрудник.
  При неизвестном сотруднике подпись «сотрудник колледжа», а не его номер.
* Честная выгрузка CSV, счётчик «дольше суток», поиск по ФИО.
* Разделы: Данные (только владелец, без консоли SQL, без DROP/ALTER), Тест
  (служебный, для проверки живого бота).
* «Аналитика» убрана из меню намеренно, но раздел и маршрут живы
  (`HIDDEN_ON_PURPOSE`).

### Мост «телефон → ассистент» (новое, выключен по умолчанию)
* Владелец пишет боту с командного слова (`BRIDGE_PREFIX`, по умолчанию `!`),
  задание попадает в очередь, программа на компьютере выполняет его, ответ
  возвращается в тот же чат MAX.
* Ворота: **только** ID из `ROOT_IDS`, строгое сравнение. Студент не пройдёт,
  это проверяется тестом.
* Служебные адреса живут в отдельной службе `bridge_service.py` на собственном
  роутере с префиксом `/bridge`. В общем приложении панели их нет вовсе, а в
  службе моста нет адресов панели.
* Порядок доступа: порт моста опубликован как `127.0.0.1:8090:8090`, поэтому
  система не принимает на нём соединений из сети. Поверх — обязательный токен.
  Проверки «запрос с этой машины» внутри бота нет: она не работает с Docker (см.
  грабли ниже), а ослабленная до «шлюза виртуальной сети» не проверяла бы
  ничего.
* Замок между консолью и мостом: кто начал — тот держит; вторая сторона ждёт;
  упавший держатель освобождает проект сам.
* Если проект держит консоль, мост **возвращает** задание в очередь и объясняет
  владельцу, почему ждёт, вместо того чтобы молчать.

## 2. Что НЕ сделано и почему

| Что | Почему |
|---|---|
| Перенос на bot-lpc.ru | Ждёт от владельца: IP, пользователь SSH, версия Linux, переносим ли живую базу, гасим ли бота на этом компе. План: `ПЕРЕНОС-БОТА-НА-СЕРВЕР.txt` на рабочем столе |
| Уведомления сотруднику 2857023211 | MAX отдаёт 404 `dialog.not.found` — бот не может ему писать. `notify()` гасит уведомления, чтобы не сыпать ошибками в журнал |
| «Полностью поменять стилитику» панели | Сделаны точечные правки и переработка темы. Визуальный образ прежний — это отдельная работа, не сделанная |
| Мост на сервере | Код моста серверу не мешает, но настройки (`BRIDGE_TOKEN`, токен службы) на сервере нужно задать отдельно |
| Мост работает только пока включён этот компьютер | Бот живёт здесь же, в Docker. Пока ты вышел из Windows, писать боту некуда. Снимается переносом на сервер |

### Про мост честно
Раньше я обещал, что мост удаляется одним файлом. На деле получилось три файла и
одна строчка:

* `handlers/bridge.py` — ворота
* `store/bridge.py` — очередь
* `web/bridge.py` — служебные адреса
* одна проверка в `bot.py` перед `menus.on_message`

Следы в `database.py` (таблица), `config.py` (настройки), `store/__init__.py`
и `repository.py` (экспорт) остаются безвредными: пустая таблица и неиспользуемые
переменные работу не меняют.

## 3. Как проверять

### Тесты
```
$env:PYTHONUTF8="1"; cd C:\BOT-LPC
.\.venv\Scripts\python.exe -X utf8 -m pytest -q          # всё
.\.venv\Scripts\python.exe -X utf8 -m pytest -q -m "not panel"   # быстро
.\.venv\Scripts\python.exe -m ruff check --select F,E9 .
```

### Бот
```
docker compose -p bot-lpc build bot
docker compose -p bot-lpc up -d bot
Invoke-RestMethod http://127.0.0.1:8080/health | ConvertTo-Json
```
Панель снаружи: `https://adamantly-emulated-shelduck.cloudpub.ru/panel`

### Вёрстка
Живой браузер, не на глаз:
```
python C:\Users\mafia\AppData\Local\Temp\opencode\check_layout.py
```
Проверяет 1440px и 820px по всем 16 страницам. Целевой результат — ноль
замечаний.

### Мост
```
python bridge_worker.py --status     # что в очереди, кто держит проект
python bridge_worker.py --once      # одно задание и выход
python bridge_worker.py             # работать фоном
```

**Программа-мост должна быть запущена на этой машине.** Пока ты вышел из Windows,
программы нет, а бот живёт в Docker на этом же компьютере — писать ему будет
некуда, и задание будет копиться в очереди до следующего входа. Это устройство,
а не поломка: перенос бота на сервер вопрос снимает.

Автозапуск при входе в Windows настроен файлом в папке автозагрузки:
```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\Мост - ответы в MAX.cmd
```
Задача в планировщике не создалась: запись в него на этой машине закрыта
(ошибка 0x80070005), и повышать права ради этого нельзя. Программа сообщает,
какой способ сработал. Пересоздать: `python bridge_worker.py --install`.

Проверить, что программа жива, не читая журнал:
```
Get-CimInstance Win32_Process -Filter "Name='pythonw.exe'" |
    Where-Object { $_.CommandLine -like "*bridge_worker*" }
```
Два процесса - это нормально: `pythonw` из `.venv` запускает настоящий
интерпретатор. Второй экземпляр программа к себе не пускает (метка
`bridge_worker.pid` с проверкой живости номера).

### Что где лежит на этой машине (вне проекта)
```
%LOCALAPPDATA%\botlpc\
    bridge_worker.json   настройки: адрес, токен, пароль opencode
    bridge_worker.log    журнал
    bridge.lock          замок «кто держит проект»
    bridge_worker.pid    метка «программа работает»
    start_bridge.vbs     отвязанный запуск
```
Всё это вне папки проекта намеренно: там токен и пароль, а папка проекта
попадает в сборку образа и в архивы.
Проверить границу доступа (ожидаемые коды важнее самих проверок):
```
Invoke-WebRequest http://127.0.0.1:8090/bridge/next                              # 403
Invoke-WebRequest http://127.0.0.1:8090/bridge/next -Headers @{"X-Bridge-Token"=$t}  # 200
Invoke-WebRequest http://127.0.0.1:8080/bridge/next                              # 404
Invoke-WebRequest http://127.0.0.1:8090/panel/login                             # 404
```

Проверить вручную: с телефона написать боту `! посмотри, что с расписанием на
завтра`. Ожидание: бот отвечает «Принял», через минуту-две приходит отчёт.

## 4. Правила, которые нельзя нарушать

1. **Не пушить в `main` без бекапа.** Сейчас это не обещание, а git-хук
   `pre-push`: он сам ставит метку `backup/ГГГГ-ММ-ДД-ЧЧММСС` и копирует базу в
   `backups/`. Если копия не вышла — пуш останавливается. Обход есть
   (`BOTLPC_SKIP_DB_BACKUP=1 git push`) и он виден в записи.
2. **В журнал `admin_log` не писать значения полей и переписку** — только имена.
3. **Коды приглашений в журнал не писать.**
4. **CSRF на всех POST.**
5. **Комментарии, интерфейс, README и отчёты — по-русски.**
6. **Вёрстку проверять браузером.**
7. **Правки файлов — временными скриптами, не редактором.** Кириллица ломается
   при записи через `write_text` без BOM; `write_bytes` с сохранением BOM
   работает. Правку проверять **чтением с диска**, а не сообщением скрипта.
8. **Не выключать ПК без явной команды владельца.**
9. **Не придумывать структуру меню вместо владельца.**

## 5. Как устроен код

```
bot.py              — точка входа: разбор обновлений MAX, врезка моста, веб-панель
config.py           — настройки из окружения
database.py         — схема, миграции, время (Asia/Yekaterinburg)
clock.py            — единственный источник «сейчас» в проекте
repository.py       — фасад поверх store/
store/              — SQL по смыслу: люди, обращения, мост, расписания
handlers/           — логика бота: меню, обращения, приглашения, FAQ, мост
web/                — веб-панель по разделам
webpanel.py         — сборка панели
panel_theme.py      — тема оформления
max_api.py          — клиент MAX API
bridge_lock.py      — замок между консолью и мостом (только на этой машине)
bridge_worker.py    — программа моста (только на этой машине)
backup_before_push.py — бекап перед пушем
bridge_service.py    — отдельная служба: только адреса моста, порт 8090
```

`bridge_lock.py`, `bridge_worker.py` и `backup_before_push.py` **не попадают в
контейнер**: в `Dockerfile` файлы перечислены поимённо. Бот от них не
зависит, и `test_dockerfile_modules` это проверяет — иначе исключением можно
было бы спрятать настоящую зависимость.

`bridge_service.py`, наоборот, копируется в образ: это вторая служба того же
контейнера. Контейнер запускает обе: мост на 8090, бота на 8080.

Настройки программы-моста лежат **вне проекта**, в
`%LOCALAPPDATA%\botlpc`: там токен и пароль службы opencode, а папка проекта
попадает в сборку образа и в архивы.

## 6. Известные грабли этого проекта

Записано, потому что каждый раз стоило времени:

* **Запятая после последней колонки** в `CREATE TABLE` — SQLite отказывается
  создавать базу. Падает только при `init_db`, то есть в самый неподходящий
  момент.
* **`db.run` возвращает `lastrowid`, а для `UPDATE` всегда 0.** Где важно, что
  правка произошла, берётся `db.run_count`. Написано и в самой базе.
* **Фикстура `env` в conftest сбрасывает `config.ROOT_IDS` в пустой список.**
  Фикстура, которая задаёт владельца, обязана зависеть от `env`, иначе её
  настройки затрутся. Забыто — ворота молча не срабатывали.
* **Список модулей для подмены `api` в conftest больше не придётся пополнять:**
  подменяются методы самого объекта. Проверка
  `test_nothing_can_reach_the_network` сама находит, если метод забыт.
* **`await x[0]` — это `await (x[0])`.** Нужно `(await x)[0]`.
* **Проверка «запрос с этой машины» внутри бота не работает с Docker.**
  Docker Desktop публикует порт через виртуальную машину, и бот видит адрес её
  шлюза даже для запроса с этой же машины. Мост с этой машины получал отказ.
  Границу держит порт, слушающий только локально на хосте.
* **`opencode run --format json` печатает поток событий, а не объект с
  ответом.** Ответ лежит в событиях `{"type":"text",...,"part":{"text":...}}`.
  Поиск ключа `response` даёт «ответ пустой». При смене формата об этом говорит
  подсказка в сообщении об ошибке — она перечисляет встреченные типы событий.
* **Присваивание модульной переменной внутри функции без `global` делает её
  локальной.** Ошибки нет, код есть, толку нет: подсказка всегда молчит.
* **Регулярка с закрывающей кавычкой ищет последнее двоеточие, а не первое.**
  Публикация порта docker записывается тремя частями: `адрес:порт:порт`.
* **Эта версия FastAPI подключает роутер лениво**, одним объектом
  `_IncludedRouter`. Перечень `app.routes` не показывает реальные адреса -
  проверять надо поведением через TestClient.
* **В PowerShell `opencode.ps1` не запускается** — только через `cmd /c`.
* **На Windows имя `python` может указывать на заглушку Microsoft Store.**
  Хук `pre-push` это учитывает: кандидат проверяется настоящим запуском.
* **Git разбирается с адресом получателя раньше, чем зовёт `pre-push`.** Проверять
  блокировку пуша можно только с настоящим приёмником.
