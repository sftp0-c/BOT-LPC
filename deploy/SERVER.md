# Запуск бота колледжа «Навигатор ЛПК» на сервере

Инструкция для человека, у которого есть сервер, и его нейросети. Сделано так,
чтобы идти по шагам и ничего не додумывать. Каждый шаг заканчивается проверкой,
по которой видно, получилось или нет.

Если что-то не совпало с ожидаемым результатом - **остановись и не иди дальше**.
Дальнейшие шаги рассчитаны на то, что предыдущий удался.

---

## Что здесь лежит и что нужно от владельца

Бот - это контейнер Docker с веб-панелью. Наружу торчит только панель, сам бот в
интернет не выходит: он сам спрашивает MAX, публичный адрес ему не нужен.

| Что | Откуда берётся | Обязательно |
|---|---|---|
| Код | Приватный GitHub-репозиторий, клон на сервер | да |
| Файл `.env` | Владелец передаёт вручную, в git его нет и быть не должно | да |
| Файл `database.db` | Владелец передаёт вручную, это живая база со всеми обращениями | да |
| DNS-запись на домен | Владелец ставит у регистратора | да |

**Токен бота и пароль панели лежат в `.env`.** У того, у кого сервер, будет
полный доступ к боту и ко всей переписке со студентами, включая их ФИО и
документы. Это не файл с настройками, это ключи и персональные данные.

---

## Шаг 1. Проверить, что сервер подходит

Нужно: Linux, 1-2 ГБ памяти, 20 ГБ места, открытые снаружи порты **80** и **443**.

```bash
cat /etc/os-release
free -h
df -h /
```

Ждём увидеть дистрибутив (например, Ubuntu 22.04 или Debian 12), свободную
память и свободное место.

---

## Шаг 2. Поставить Docker

Порт бота на этом сервере - **8090**, потому что стандартный 8080 занят другим
приложением. Во всех командах ниже порт 8090.

```bash
apt update
apt install -y docker.io docker-compose-plugin nginx certbot python3-certbot-nginx
docker --version
docker compose version
```

Ждём увидеть версию обоих. Если `docker compose version` ругается, что плагина
нет, поставь его по инструкции Docker для твоего дистрибутива и вернись сюда.

---

## Шаг 3. Получить ключ для приватного репозитория

Репозиторий приватный, поэтому `git clone` без прав не пройдёт.

Способ A - ключ для чтения (предпочтительно). Владелец передал тебе строку с
ключом. Тогда:

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
# вставь строку, которую дал владелец, целиком - это одна длинная строка
echo 'ssh-ed25519 AAAA...' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

Способ B - токен GitHub, если ключа нет:

```bash
git clone https://<ТОКЕН>@github.com/sftp0-c/BOT-LPC.git /opt/bot-lpc
```

---

## Шаг 4. Склонировать код

```bash
mkdir -p /opt/bot-lpc
git clone https://github.com/sftp0-c/BOT-LPC.git /opt/bot-lpc
cd /opt/bot-lpc
git log -1 --oneline
```

Если клон сработал с ключом из шага 3 - сработает и тут. Если ругается
`Permission denied (publickey)` - вернись к шагу 3.

Ждём увидеть коммит. Рекомендуемая версия: **1.4.0**.

---

## Шаг 5. Положить `.env`

Владелец передал файл `.env` - сохрани его в `/opt/bot-lpc/.env`.

Проверь, что он лежит и не пустой:

```bash
ls -la /opt/bot-lpc/.env
```

В нём владелец уже должен поменять четыре вещи. Сверься глазами:

| Переменная | Должно быть | Зачем |
|---|---|---|
| `PUBLIC_URL` | `https://bot-lpc.ru` | ссылки-приглашения сотрудникам |
| `TUNNEL_ENABLED` | `0` | туннель Cloudflare на сервере не нужен |
| `BACKUP_EVERY_HOURS` | `6` | автокопия базы каждые 6 часов |
| `BACKUP_DIR` | `/app/data/backups` | куда складывать копии |

**Проверь, что `.env` не попадёт в git.** Это обязательно, токен не должен
утечь:

```bash
cd /opt/bot-lpc
git check-ignore -v .env
```

Ждём увидеть строку вида `.gitignore:2:.env .env`. Если `.env` не игнорируется -
**остановись**, это дыра, скажи владельцу.

---

## Шаг 6. Положить живую базу

Владелец передал файл `database.db`. Положи его в `/opt/bot-lpc/import/`:

```bash
mkdir -p /opt/bot-lpc/import
# скопируй сюда database.db, который дал владелец
ls -la /opt/bot-lpc/import/
```

База лежит не в папке проекта, а внутри тома Docker. Создаём том и кладём файл
туда **до первого запуска** - иначе бот создаст пустую базу, и потом придётся
подменять.

```bash
docker volume create bot-lpc-data
docker run --rm   -v bot-lpc-data:/data   -v /opt/bot-lpc/import:/import:ro   alpine sh -c 'cp /import/database.db /data/database.db && chown -R 10001:999 /data && ls -la /data'
```

Про `10001:999`: это пользователь внутри контейнера, проверено командой `id` в
живом контейнере. Если права не выставлены, бот упадёт с отказом в доступе при
первой же записи.

Ждём увидеть `database.db` и владельца `10001 999`.

---

## Шаг 7. Накрыть compose так, чтобы порт не торчал наружу

```bash
cp /opt/bot-lpc/deploy/docker-compose.override.yml /opt/bot-lpc/docker-compose.override.yml
cd /opt/bot-lpc
docker compose config | head -40
```

Ждём увидеть в выводе порт `127.0.0.1:8090`. Если там `0.0.0.0:8090` - **остановись**,
панель выставлена в интернет мимо nginx и без сертификата.

---

## Шаг 8. Поднять бота

Поднимаем **только бота**. Службу туннеля не запускаем: на сервере наружу
смотрит nginx, а адрес туннеля случайный и меняется при каждом перезапуске.

```bash
cd /opt/bot-lpc
docker compose images                 # запомни ID образа ДО сборки
docker compose up -d --build bot
docker compose images                 # ID обязан смениться
```

`--build` обязателен: без него контейнер просто перезапустит старый образ, и ты
решишь, что всё обновилось, а код старый.

Проверка, что бот живой:

```bash
curl -s http://127.0.0.1:8090/health
```

Ждём примерно такое: `{"ok":true,"version":"1.4.0","platform":"MAX","mode":"polling",...}`

Если `ok` не true - смотри логи:

```bash
docker compose logs --tail=100 bot
```

---

## Шаг 9. nginx и сертификат

```bash
cp /opt/bot-lpc/deploy/nginx/bot-lpc.conf /etc/nginx/sites-available/bot-lpc
ln -s /etc/nginx/sites-available/bot-lpc /etc/nginx/sites-enabled/bot-lpc
rm -f /etc/nginx/sites-enabled/default
nginx -t
systemctl reload nginx
```

Ждём от `nginx -t`: `syntax is ok` и `test is successful`.

Теперь выпустить сертификат. **DNS-запись должна уже указывать на этот сервер**,
иначе certbot не сможет её подтвердить:

```bash
certbot --nginx -d bot-lpc.ru -d www.bot-lpc.ru
```

Ждём сообщение об успешном выпуске и предложение перезагрузить nginx - согласись.

Проверка:

```bash
curl -sI http://bot-lpc.ru/panel | head -5
curl -s https://bot-lpc.ru/health
```

Первое должно отдавать переход на https, второе - `ok: true`.

## Шаг 10. Кто чем проверяет

| Проверка | Кто |
|---|---|
| `/health` отвечает `ok` | ты, с сервера |
| nginx отдал сертификат | ты, с сервера |
| Панель открывается в браузере и пускает со входом | владелец, с телефона |
| Бот отвечает в MAX | владелец |

## Главное про переключение

**Токен бота один, а бот должен быть один.** Если серверный бот и компьютер
владельца работают одновременно, два процесса с одним токеном начнут мешать
друг другу, и события в MAX будут теряться или дублироваться.

Правильный порядок:

1. Поднять сервер и убедиться, что он встал (шаги 1-9).
2. **Владелец останавливает бота на своём компьютере:**
   ```bash
   docker compose -p bot-lpc stop
   ```
3. Владелец проверяет бота в MAX.
4. Если не так - владелец возвращает всё как было:
   ```bash
   docker compose -p bot-lpc start
   ```

Данные при этом целы: том остаётся на месте, и копия базы тоже остаётся.

---

## Откат, если что-то пошло не так

Вернуть всё на компьютер владельца одной командой (делает владелец):

```bash
docker compose -p bot-lpc start
```

Вернуть более старый код на сервере:

```bash
cd /opt/bot-lpc
git log --oneline -5
git checkout <старый-хеш>
docker compose up -d --build bot
curl -s http://127.0.0.1:8090/health
```

Схема базы при откате не откатывается - лишние колонки останутся и не помешают.
Это сделано специально, чтобы откат был безопасным.

---

## Обновления после переноса

Кто-то пушит новую версию в репозиторий. На сервере после этого:

```bash
cd /opt/bot-lpc
git pull
docker compose images                 # ID ДО сборки
docker compose up -d --build bot
docker compose images                 # ID обязан смениться
curl -s http://127.0.0.1:8090/health
```

**Три проверки обязательны.** Сборка печатает «Image built» даже когда падает
ниже по логу, и один раз из-за этого бот три часа работал на старом коде при
зелёном `/health`. Верь ID образа и содержимому, а не надписи в конце вывода.

---

## Перезагрузка сервера

Ничего делать не нужно: в `docker-compose.yml` уже стоит `restart: unless-stopped`,
бот и nginx поднимутся сами.

---

## Чего делать нельзя

* **Не запускать на сервере одновременно с компьютером владельца.** Один токен -
  один бот.
* **Не коммитить `.env` и `database.db` в git.** Это токен бота, пароль панели и
  персональные данные студентов. В `.gitignore` они уже есть, но проверь на шаге 5.
* **Не убирать nginx.** Панель с паролем по обычному HTTP отдаёт пароль открытым
  текстом.
* **Не запускать службу `tunnel`.** Она для домашнего компьютера, на сервере
  адрес случайный и меняется при перезапуске.
* **Не менять `docker-compose.yml` в репозитории.** Для сервера есть
  `docker-compose.override.yml`; правка основного файла сломает доступ владельца
  с телефона в домашней сети.

---

Собери и пришли владельцу вывод этих четырёх команд - по нему видно почти всё:

```bash
cd /opt/bot-lpc && docker compose ps
cd /opt/bot-lpc && docker compose logs --tail=80 bot
curl -s http://127.0.0.1:8090/health
nginx -t
```
