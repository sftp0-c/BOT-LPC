# BOT-LPC — описание проекта

Подробное описание того, из чего состоит бот колледжа: стек, файлы, база,
маршруты, соглашения и история решений. README отвечает на вопрос «как
запустить и что умеет», этот файл — «как оно устроено внутри и почему так».

Снимок сделан 29 сентября 2026 года, на коммите `a1b2c3d`. Числа в документе
(строки, тесты, маршруты) меняются — сверяйтесь с `git log`.

---

## 1. Что это

Бот для мессенджера **MAX** (российский мессенджер, не Telegram) для
БУ «Лангепасский политехнический колледж». Студенты пишут боту, он
показывает расписание своей группы, принимает обращения и переписку
«студент ↔ сотрудник», отвечает на частые вопросы и зовёт сотрудников.
Отдельная веб-панель для системных администраторов.

Одно приложение, три роли в одном коде: бот в мессенджере, панель в браузере
и JSON-API для скриптов. Всё на одной базе SQLite, всё на одном процессе
uvicorn.

```
   MAX API ──► bot.py ──► handlers/* ──► repository.py ──► database.py ──► SQLite
                 │                                                     ▲
                 └──► webpanel.py (FastAPI) ───────────────────────────┘
                       94 маршрута, /panel + /health + JSON-API
```

## 2. Стек

| Слой | Что | Версия | Зачем именно это |
|------|-----|--------|------------------|
| Язык | Python | 3.12 | `asyncio` без внешнего цикла событий |
| Веб | FastAPI | ≥0.116,<1 | асинхронный сервер + автодокументация, панель отдаётся тем же процессом |
| Сервер | uvicorn[standard] | ≥0.35,<1 | ASGI-сервер, поднимается в контейнере |
| HTTP-клиент | httpx | ≥0.28,<1 | запросы к MAX API и на сайт колледжа |
| База | SQLite через aiosqlite | ≥0.21,<1 | файл, ноль администрирования, бэкап = копия файла |
| Переменные окружения | python-dotenv | ≥1.1,<2 | `.env` читается при старте |
| Загрузка файлов | python-multipart | ≥0.0.20,<1 | формы панели и прикрепление документов |
| Разбор PDF | pdfplumber | ≥0.11,<1 | единственная тяжёлая зависимость: расписание из PDF |
| Часовые пояса | tzdata | ≥2025.2 | Екатеринбург в тонком linux-образе |
| Контейнеры | Docker + compose | — | воспроизводимая сборка, healthcheck, том с данными |
| Тесты | pytest | — | 1534 теста, `asyncio_mode = auto` |

Внешних сервисов, кроме API MAX и сайта колледжа, нет. Ни Redis, ни
PostgreSQL, ни очередей задач, ни внешнего фронтенда: панель — это HTML,
собранный на сервере, и CSS без единой строки JavaScript.

**Почему SQLite, а не PostgreSQL.** База целиком помещается в файл, который
копируется для резервной копии. В панели есть согласованный снимок рабочей
базы через `VACUUM INTO` — на PostgreSQL это была бы отдельная механика.
Один процесс, один файл, ноль обслуживания. Плата — запись сериализуется,
но бот college-scale (десятки одновременных пользователей) в это упирается
не скоро.

**Почему pdfplumber.** Расписание приходит с сайта колледжа в PDF, и
студент должен видеть его текстом в чате, а не ссылкой. Разбор таблиц
нужен настоящий: коды групп в шапке, ячейки вида «предмет / вид занятия /
преподаватель», колонка «ауд.». Альтернативы (`PyPDF2`, `pdfminer` напрямую)
не дают координаты ячеек.

**Почему без JavaScript.** Панелью пользуется администратор, а не фронтендер,
и она должна открываться с телефона через медленный мобильный интернет.
Вся интерактивность — обычные формы и CSS: тёмная тема через
`prefers-color-scheme`, графики через инлайновый SVG, анимации через
`@keyframes`. Скрипт сломал бы всю панель целиком, и чинить его пришлось бы
на телефоне.

### Тесты — 1599 штук

Лежат в `tests/`, запускаются одной командой. Из них 245 помечены `panel`
(идут через `TestClient` и медленнее), остальные — `not panel`. Есть маркер
`slow`: поднимает базу заново и трогает схему.

```powershell
$env:PYTHONUTF8="1"
cd C:\BOT-LPC
.\.venv\Scripts\python.exe -X utf8 -m pytest -q                 # всё
.\.venv\Scripts\python.exe -X utf8 -m pytest -q -m "not panel"  # быстро
.\.venv\Scripts\python.exe -X utf8 -m pytest -q -m "panel"      # только панель
```

Тихий прогон `-m "not panel"` занимает около 4 минут 30 секунд, полный — от
5 до 8 минут. Разница заметна, поэтому частые проверки делаются тихим прогоном,
а перед коммитом — полным.

### Схема проверяется, а не предполагается

Если таблицу удалили руками или потерялась колонка, страницы панели не падают
с 500. Вместо этого показывают, чего не хватает, и кнопку «🔧 Восстановить
схему»: создаются недостающие таблицы, индексы и колонки, остальные данные не
трогаются. То же происходит автоматически при перезапуске бота. Состояние
видно в `/health` (поле `missing_schema`) и в `/panel/api/health`.

Тест `tests/test_dockerfile_modules.py` следит, чтобы список модулей в
`Dockerfile` не отставал от реальности: забытый `COPY` означал бы падение на
старте контейнера в три часа ночи.

### Служебные таблицы можно чистить

Кнопка «🧹 Почистить» на странице базы трогает только `processed_updates`,
`login_attempts` и `user_states` — то, что растёт само и ничего не значит.
Обращения, сообщения, сотрудники и реестр пользователей чистка не трогает
никогда.

### Часовой пояс хранится вместе со временем

`created_at` и подобные поля — naive-строки вида `ГГГГ-ММ-ДД ЧЧ:ММ:СС` **в
локальном времени колледжа**. Часовой пояс известен изнутри `clock.py` и не
теряется по дороге. Подробности в разделе 8.---

## 5. Панель сис-админа

FastAPI-приложение, отдаётся тем же процессом, что и бот. Путь `/panel`,
вход по MAX ID и паролю `WEB_PANEL_PASSWORD`. Пока пароль пуст, панель
отвечает 503 и ничего не показывает.

### 94 маршрута

36 страниц (`GET`) и 58 форм (`POST`). Страницы: обзор, лента событий,
рабочее место обращений, реестр людей, студенты, сотрудники, «без прав»,
коды и заявки, колледж, группы, расписания, рассылки, настройки, база
данных, журнал, аналитика, шаблоны, поиск, выгрузки CSV и JSON-API.
Формы: вход и выход, действия с обращениями (ответ, статус, архив, удаление,
массовые), сотрудники, коды, права, группы, расписания и звонки, рассылки,
настройки, обслуживание базы, резервные копии, FAQ.

### Пять групп навигации вместо шестнадцати вкладок

```
Пульт        Обзор · Лента событий
Обращения    Рабочее место · Шаблоны · Аналитика
Люди         Реестр · Студенты · Сотрудники · Без прав · Коды и заявки
Справочники  Колледж · Группы · Расписания · Рассылки
Система      Настройки · База данных · Журнал
```

Пути не менялись: старые `/panel/<раздел>` работают как раньше, тесты и
ссылки из отчётов не ломаются. На широком экране боковое меню, на узком —
одна прокручиваемая строка сверху, а не пятнадцать плиток во весь экран.

Бейджи показывают, сколько в группе ждёт внимания: обращения, люди,
справочники. Поиск по разделам — `Ctrl+K`. Горячие клавиши работают и на
странице, и в полях.

### Рабочее место обращений

Очередь слева, выбранное обращение справа, на одном экране. Отдельной
страницы карточки нет: старые ссылки `/panel/tickets/12` открывают рабочее
место с уже выбранным обращением.

Редактируется всё, что у обращения бывает: текст, категория, тема,
ответственный, статус, кабинет выдачи, срок готовности. Пустое поле не
затирает старое значение, каждое изменение попадает в историю с именем
того, кто поменял.

Массовые действия: отметили несколько обращений галочкой — назначить
сотрудника, сменить статус, поставить кабинет, убрать в архив.

### Дизайн-система

`panel_theme.py` — 1541 строка, 89 CSS-переменных, 55 SVG-иконок, 11
анимаций, 6 медиазапросов.

- тёмная тема по умолчанию, светлая — переключателем в шапке и по системной
  настройке; печать всегда светлая;
- SVG-иконки вместо эмодзи: эмодзи рисуются по-разному на разных системах
  и в тёмной теме выглядят пятнами;
- анимации: появление карточек, раскрытие списков, рост полосок графиков,
  скелетоны, тосты, счётчик. Всё отключается при `prefers-reduced-motion`;
- графики — чистый SVG, цвета берутся из токенов темы, у столбиков и долей
  есть подсказки при наведении.

### Что делает панель удобной на телефоне

- при ширине до 1000 px боковое меню становится верхней лентой;
- рабочее место становится одной колонкой;
- широкие таблицы прокручиваются внутри карточки и не растягивают страницу;
- при ширине до 640 px кнопки и пункты меню вырастают до 44 px (палец, а не
  курсор), поля ввода получают шрифт 16 px (иначе телефон зумит страницу),
  подписи таблиц становятся плотнее, второстепенные строки шапки скрываются.

### Безопасность

- вход: сессия в подписанной куке, пароль сравнивается через `secrets`;
- каждая форма — с CSRF-токеном, необратимые действия спрашивают
  подтверждение;
- ограничение попыток входа: таблица `login_attempts`;
- ограничение подбора кода сотрудника: `STAFF_CODE_ATTEMPTS` в час с одного
  MAX ID, о превышении сис-админы получают уведомление;
- код одноразовый: погашение проверяется и снимается одной атомарной
  операцией, поэтому два человека с одной ссылкой не пройдут;
- служебные ключи настроек скрыты белым списком `HUMAN_SETTINGS` — в
  редакторе видны только четыре понятных человеку ключа, остальное живёт в
  `.env` и в других формах панели.

### Полное ФИО вместо обрезки

Раньше ФИО склеивалось с группой в одну строку и резалось до 40 символов: в
очереди, в шапке карточки и в списках сотрудников человек узнавался по
обрезку. Теперь `fio(name, user_id, limit=0)` — единственное место в панели,
где ФИО можно укоротить; обрезка идёт по границе слова и без многоточия.
Пустое ФИО даёт «ID 300» через `person_label`, а не сырой идентификатор.
В списках сотрудников ФИО стоит в пункте целиком, а должность — в `title`.

## 6. Бот в мессенджере

### Команды

MAX не показывает боту нижние кнопки под полем ввода: по документации бот
умеет присылать только inline-кнопки, а нижнее меню собирается из команд
(`PATCH /me/commands`). Поэтому меню сделано командами — они работают и
руками, и кнопкой рядом с именем бота.

| Команда | Что делает | Кому |
|---------|-----------|------|
| `/menu` | главное меню | всем |
| `/schedule` | расписание: неделя, сегодня, ближайшие | всем |
| `/today` | пары на сегодня | всем |
| `/tickets` | мои обращения | всем |
| `/new_request` | новое обращение | всем |
| `/profile` | профиль и группа | всем |
| `/teacher` | расписание преподавателя | всем |
| `/queue` | очередь обращений | сотрудникам |
| `/stats` | статистика | сотрудникам |
| `/help` | что умеет бот | всем |
| `/view` | переключить режим просмотра | сис-админам |
| `/admin` | кабинет сис-админа | сис-админам |

Служебные: `/start`, `/cancel`, `/id`, `/supersecret_admin`, `/logs`,
`/test`, `/panel`, `/join КОД`.

Команда ведёт ровно туда же, куда соответствующая кнопка, и закрывается
правами: студенту `/queue` показывает его меню, а не чужую очередь.

### Реестр обработчиков

`handlers/registry.py` — два словаря и два декоратора. Обработчики
регистрируются в момент импорта модулей, поэтому порядок импортов задан
в `bot.py` и важен.

```python
@callback("tickets:open")   # кнопка с payload
@state("reg:name")         # шаг диалога
```

### Меню студента

Семь кнопок, а не пятнадцать: редкие действия уехали в подменю. Меню
содержит конкретные обращения («📄 Справки», «🎓 Учёба», «💰 Стипендия»,
«💬 Другое») вместо одного «нового обращения» с двумя шагами выбора.
Жалоба на ошибку в боте осталась на видном месте в одном нажатии и работает
даже тогда, когда должности сотрудников ещё не назначены.

### Черновик обращения

Первое сообщение не создаёт обращение: текст сохраняется, снизу появляются
кнопки «✉️ Отправить обращение», «🗑 Очистить черновик» и «↩️ В меню».
Можно написать несколько сообщений подряд — они склеятся в один текст, —
и отменить всё одним нажатием, не создавая обращения.

### Роли

| Роль | Что может |
|------|-----------|
| Студент | расписание, свои обращения, FAQ, справочник колледжа |
| Сотрудник | очередь своих обращений, ответы, статусы, внутренние заметки, шаблоны, передача другому сотруднику, статистика по своим |
| Сотрудник с правом «видит все» | то же, но по всем обращениям |
| Сотрудник в отпуске | новые обращения к нему уходят заместителю |
| Сис-админ | всё: реестр, коды, права, группы, расписания, рассылки, база, настройки, журнал |
| Владелец (`ROOT_IDS`) | максимальные права, снять их нельзя ни в боте, ни в панели |

Системный администратор видит все обращения независимо от настроек
сотрудников. Кнопка «✅ Готово» закрывает обращение только если человек —
ответственный за него, сис-админ или сотрудник с правом «видит все»: раньше
проверялось лишь «ты сотрудник», и чужой сотрудник мог закрыть чужое дело.

### Согласие на обработку данных

При первой регистрации бот просит согласие и только потом сохраняет ФИО и
группу. Текст правится в панели, дата и редакция хранятся рядом с профилем
(`users.consent_at`, `users.consent_version`). Уже зарегистрированным людям
согласие не докучает: список тех, кто его не давал, виден в панели фильтром
«только без согласия».

### Режим просмотра

Сис-админ может посмотреть на бота глазами любой роли — удобно для проверки
и показа. Обычному сотруднику переключатель не показывается, команда `/view`
для него закрыта, а сохранённый ранее режим сбрасывается в «сотрудник»:
забытый переключатель приводил к тому, что сотрудник писал студенту вместо
коллеги.

## 7. Расписание

Ссылку на PDF задаёт сис-админ. Бот скачивает файл, разбирает его в
занятия и хранит их в таблице `lessons`, поэтому студент видит расписание
текстом в чате, а не ссылкой.

### Разбор PDF

Колледж кладёт в шапку каждой страницы дату («День — Понедельник,
28.09.2026»), таблицу с кодами групп, ячейки вида «предмет / вид занятия /
преподаватель» и колонку «ауд.». Коды групп распознаются и как `24-21(2С)`,
и как `ИС-21`. Таблицы ищутся сначала по рамкам, а если их нет — по
колонкам пробелов.

Время в PDF не содержится — оно подставляется по номеру урока из звонков.
Номер в PDF — это **урок**, а не пара: в паре уроков два.

| Урок | Время | Пара |
|------|-------|------|
| 1 | 08:00–08:45 | 1 пара, 1 урок |
| 2 | 08:50–09:35 | 1 пара, 2 урок |
| 3 | 09:50–10:35 | 2 пара, 1 урок |
| 4 | 10:55–11:40 | 2 пара, 2 урок |
| 5 | 12:00–12:45 | 3 пара, 1 урок |
| 6 | 13:05–13:50 | 3 пара, 2 урок |
| 7 | 14:00–14:45 | 4 пара, 1 урок |
| 8 | 14:50–15:35 | 4 пара, 2 урок |
| 9 | 15:45–17:15 | 5 пара (один урок) |
| 10 | 17:25–18:55 | 6 пара (один урок) |
| 11 | 19:00–20:30 | 7 пара (один урок) |

Звонки правятся в панели: общий список и отдельно для одной пары в
карточке группы. Запись может быть и по парам
(`{"1": [["08:00","08:45"],["08:50","09:35"]]}`) — развернётся в номера
уроков подряд. Изменение сразу пересчитывает время у уже разобранных
занятий, перечитывать PDF не нужно.

### Неделя берётся из самого PDF

`timetable.week_of_pages()` находит самую раннюю дату и запоминает
понедельник этой недели в `GroupSchedule.week`. В шапке расписания
показывается именно эта неделя, а не текущая, — иначе на стыке недель
студент сверялся бы с неверной датой. Если файл старше текущей недели, бот
прямо пишет, что колледж ещё не выложил свежее расписание, и сколько дней
прошло, вместо тихого показа устаревших пар.

### Пробел после каждой пары уроков

Уроки идут парами, и в тексте между парами стоит пустая строка:

```
1 урок · 08:00–08:45 · Математика | лекция
   ауд. 204 · Иванова А. А.
2 урок · 08:50–09:35 · Математика | практика
   ауд. 204 · Иванова А. А.

3 урок · 09:50–10:35 · Физика | лаб
   ауд. 217 · Петров П. П.
4 урок · 10:55–11:40 · Физика | лаб
   ауд. 217 · Петров П. П.

5 урок · 12:00–12:45 · Информатика
   ауд. 112 · Сидоров С. С.
```

Правило: пустая строка перед уроком с нечётным номером больше 1. Перед
первым уроком и после последнего пустой строки нет, нечётный хвост из
одного урока остаётся (5 уроков: 1,2 / ПРОБЕЛ / 3,4 / ПРОБЕЛ / 5).
Между днями недели свой разделитель, а не парный.

Весь текст уроков собирается в трёх функциях `timetable.py` — `format_day`,
`format_schedule` и `format_upcoming`. Бот, панель и уведомление подписчикам
идут через них, поэтому правило живёт в одном месте и не расходится.

### Кэш и слежение

Разбор хранится в базе: повторное открытие расписания не обращается к
сайту. Через `SCHEDULE_CACHE_HOURS` (по умолчанию 12) файл скачивается
заново, и если на сервере выложили новую версию, занятия обновятся сами, а
подписчики получат уведомление с ближайшими парами. Скачанные PDF лежат в
папке `schedules` рядом с базой, держится `SCHEDULE_CACHE_FILES` файлов.

Фоновая проверка ходит на страницу с PDF раз в `WATCH_INTERVAL_HOURS`
(12 часов) и сверяет SHA-256:

- файл не изменился — не делается ничего, ни разбора, ни писем;
- файл изменился и занятия действительно другие — подписчикам групп
  приходит сообщение с ближайшими парами;
- файл перезаписали тем же содержимым — тишина, письма не летят впустую;
- недоступный или нечитаемый PDF не мешает остальным, сис-админ получает
  одно сообщение с причинами, с кулдауном 6 часов.

Уведомления получают только те, кто подписался на свою группу кнопкой
«🔔 Подписаться на обновления».

### Импорт с сайта колледжа

На странице `https://collegelan.ru/studentam/raspisanie-zanyatiy.php`
лежат 18 PDF. Автосбор берёт только те, чьё имя — две и более группы
(`[0-9]{2}-[0-9]{2}(-[0-9]{2}-[0-9]{2})+[.]pdf`), и отбрасывает всё, где в
названии есть «куратор», «консультаци» или «график». Отсекаются
`График консультаций преподавателей 2025-2026.pdf`,
`кураторы групп на 2026-2027.pdf`, `04.07-05.07.20222.pdf` и девять
архивных. Остаётся семь настоящих.

Фильтр применяется к автосбору со страницы, а не к ручной ссылке: если
сис-админ вставил в панель конкретный PDF с нестандартным именем, он
импортируется в любом случае.

### Защита от отката недели

Семь настоящих файлов лежат на странице **перед** одиннадцатью лишними,
поэтому при безусловной перезаписи последний файл побеждал бы, и свежая
неделя затиралась бы архивной. Теперь расписание для группы
перезаписывается, только если неделя нового файла не старше уже сохранённой
(`GroupSchedule.week`):

- новая неделя ≥ сохранённой — пишем (равенство не считается откатом: файл
  могли перезалить тем же содержимым);
- строго старше — не пишем и пишем в журнал, какие группы пропущены;
- неделя не определилась — ведём себя как раньше, но пишем в журнал, а не
  молчим.

### Группы: один справочник вместо написаний

Код группы приводится к одному виду при импорте, при регистрации и при
поиске расписания:

| Написал | Стало |
|---------|-------|
| `24-23 (П)` | `24-23П` |
| `24 23 п` | `24-23П` |
| `2423П` | `24-23П` |
| `24-21(2С)` | `24-21-2С` |

Похожее, но не то (`24-23` вместо `24-23П`) — бот не создаёт новую группу, а
показывает кнопки с похожими и ждёт выбора. Совсем новая группа заводится
автоматически, сис-админы получают уведомление. Таблица `group_aliases`
хранит варианты, которые правилом не сводятся (`ИС21` → `ИС-21`). Поиск по
буквам не зависит от раскладки: `P` и `П` — одна и та же группа.

## 8. Время и часовой пояс

Раньше «сейчас» бралось из двух источников: `datetime('now')` в SQLite
(всегда UTC) и `datetime.now()` в Python (локальное время машины, а в
`python:3.12-slim` — тоже UTC). В контейнере оба источника давали UTC, и
все даты в базе и в панели отставали на 5 часов от екатеринбургских:
обращение, созданное в 11:30, показывалось как 06:30.

Теперь в проекте одно время — **локальное время колледжа**, и в базе оно
хранится таким же.

### `clock.py` — единственное место, где берётся «сейчас»

- `clock.stamp()` — отметка «сейчас» для записи в базу;
- `clock.parse()` — чтение строки из базы обратно в время;
- `clock.format_when()` — человеческая строка;
- `clock.today()` — сегодняшняя дата;
- `clock.stamp_at(360)` — «сейчас плюс шесть часов» (срок действия кода).

Зона читается из переменной окружения `TZ`, по умолчанию
`Asia/Yekaterinburg`: в `tzdata` 2025+ город живёт в азиатском списке
поясов, а `Europe/Yekaterinburg` в образе — ссылка на него (её создаёт
`Dockerfile`, потому что в `tzdata` 2026c обратной ссылки нет, и без неё
время в контейнере тихо остаётся в UTC). Если зона недоступна — нет
`tzdata`, опечатка в `TZ` — бот не падает, а работает на фиксированном
UTC+5 и пишет предупреждение в журнал: перевода часов в Екатеринбурге нет,
так что это ровно то же время, только без пересчёта летнего времени.

Все функции возвращают naive-время: часовой пояс известен изнутри модуля и
никогда не теряется по дороге.

### Что заменено

- SQL вида `datetime('now', '+6 hours')` — на `clock.stamp_at(360)`;
- `utils.local_time()` больше не приводит время из базы к местному: там уже
  местное. Значение с явным сдвигом (`Z`, `+05:00`) — единственное, что
  пересчитывается;
- «сегодня», «завтра» и «5 дней назад» считаются по этому же поясу и в боте,
  и в расписании, и в панели.

### Миграция

При первом запуске после обновления `migrate_timezone()` переводит уже
накопленные записи на разницу сдвигов. Миграция идемпотентна: она
запоминает, что перевела, и второй раз ничего не двигает. Отменить можно,
удалив настройку `tz_migrated` и запустив бота ещё раз.

**Ошибка, найденная после миграции:** `utils.local_time()` считал, что
голое время из базы записано в UTC, и приводил его к местному. Пока база
писалась через `datetime('now')`, это было правильно. После перевода базы
на локальное время каждая дата панели уезжала вперёд на 5 часов:
сохранённое 12:00 показывалось как 15:00. Тест
`tests/test_local_time_display.py` на это и охотится.

### Тест, который врал о часах

`test_fmt_when_boundary_follows_given_now` брал «минус 24 часа» и «плюс два
часа» — то есть попадал ровно на полночь. После 22:00 тест краснел, и
решали это часы машины, а не код. Теперь момент берётся внутри суток,
отсчитанных от начала дня, а метка сравнивается при разном `now`.

## 9. Подписи кнопок

Кнопка в MAX помещается в одну строку, и клиент обрезает подпись многоточием
(«Должность изме…»). Это заметили на телефоне, поэтому правила считаются
**в ячейках, а не в символах**: эмодзи занимает две ячейки.

| Кнопок в ряду | Предел |
|---------------|--------|
| 1 | 20 ячеек |
| 2 | 16 ячеек |
| 3 и больше | 9 ячеек |

`BUTTON_TEXT = 20` — базовый предел, `row_limit(1|2|3+)` — по числу кнопок.
В коде не должно быть рядов шире двух кнопок, иначе предел схлопывается до
девяти ячеек и подпись обрезается.

### Правила

- `short_label()` режет по границе слова, а не по символу, и не добавляет
  многоточие;
- в кнопку влезает только имя человека, должность и отдел перечислены
  текстом над списком — их видно целиком, и «Петрова Мария Сергее…» не
  путается ни с кем;
- у обращения в кнопке остаётся номер, статус и короткая пометка, раздел
  виден в карточке;
- подменю «Обратная связь» сначала показывает должность, затем человека
  этой должности — так «Зам УРП» и «Директор» не превращаются в «Зам…»;
- тема обращения и раздел обращения разведены на две подписи: полная в
  тексте и уведомлении, короткая в кнопке (`TOPIC_CATS` / `TOPIC_CATS_BTN`,
  `STAFF_CATS` / `STAFF_CATS_BTN`);
- `short_name()` без ФИО даёт «Без имени», `person_label(name, user_id)` —
  «ID 300». **Кнопка никогда не имеет пустой подписи:** MAX на такой
  подписи отвечает `400 Field 'text' size (0)` и роняет сообщение целиком,
  вместе со всеми кнопками вокруг.

### Тесты

- `tests/test_no_ellipsis.py` — статика: обходит дерево AST (видит имена и
  внутри f-строк), проверяет все 318 рядов в исходниках;
- `tests/test_screens_no_ellipsis.py` — живой проход по 11 экранам бота;

### Правила, которые бот не нарушает

- **не выдумывает.** Там, где сайт отвечает устаревше или пусто (общежитие —
  «Отсутствует», суммы стипендии не опубликованы, правил по материнскому
  капиталу нет), в ответе прямо сказано «уточняйте» и даны телефоны;
- **не отвечает не на то.** При равном балле у двух разных вопросов бот
  молчит и предлагает написать сотруднику — лучше тишина, чем неверный ответ;
- **в кнопку — номер, а не текст.** Вопрос печатается текстом списка,
  кнопка несёт только номер, поэтому подпись никогда не режется;
- **найдено — пишем, не найдено — не выдумываем.** Голосовой ввод
  распознаётся: пунктуация, «ё/е» и повторы слов не мешают поиску.

Поиск идёт по ключевым словам с нормализацией («стипендию» = «стипендия»,
регистр, «ё/е», пунктуация). Кнопка «👎 Это не помогло» заводит обращение
сотруднику по разделу вопроса; повторное нажатие второго обращения не
создаёт. Вопросы, ответы и раздел правятся в панели.

### Заливка черновика

В таблицу `faq` при каждом старте бота заливается черновик из
`college.DEFAULT_FAQ`. Заливка **идемпотентна**: добавляются только
отсутствующие названия, ничего не перезаписывается, правки сис-админа
переживают обновление.

## 11. Обращения

### Модель данных

`tickets` — само обращение: автор, ответственный, раздел, тема, текст,
статус, кабинет выдачи, срок готовности, документ. `ticket_messages` —
переписка, включая внутренние заметки. `ticket_events` — история: кто, что и
когда поменял.

### Статусы

Новое → в работе → готово / завершено / отклонено. Отдельный флаг «ждёт
ответа» и «ждёт вашего ответа» — по нему очередь фильтруется.

### Кабинет 115 — только под справки

Долгое время 115 стоял в поле «кабинет выдачи» по умолчанию, то есть
подставлялся во всех обращениях подряд: и для справки, и для «когда сдавать
зачётку». Теперь 115 зашит **только под справки** — так сказала приёмная
комиссия.

- обращение считается справкой по разделу, по теме или по тексту — и только
  для него 115 подставляется сам;
- указанный в карточке кабинет уважается всегда, в том числе для справок:
  если сотрудник написал «каб. 7», туда и выдают;
- если кабинет не указан и это не справка, панель **не закрывает обращение
  молча** — пишет «Укажите кабинет выдачи: 115 зашит только под справки» и
  возвращает в карточку. Раньше документ помечался готовым, а студент
  оставался без ответа, где его забрать;
- кабинеты для подсказки при вводе собираются из кабинетов сотрудников плюс
  115: спрашивать «какой кабинет» бесполезно, человек не знает, что
  сотрудник сидит в 204-м.

### Архив вместо удаления

«🗄 В архив» ничего не стирает: обращение уходит из очереди, переписка и
история остаются, вернуть можно одним действием. Архивировать может
ответственный, сис-админ или сотрудник с правом «видит все»; студенту
нельзя. Студенту уходит честное уведомление. Жёсткое удаление осталось в
боте у сис-админа для неисправимых случаев, с записью в журнал и
уведомлением студента.

### Передача другому сотруднику

С комментарием или без. Студент остаётся автором, сотрудник меняется, новый
получает уведомление, история сохраняет, кто и кому передал.

### Внутренние заметки

Видит только команда, студент — никогда, в том числе в истории.

### Сотрудник в отпуске

Отметка «Отпуск до» в карточке сотрудника. Пока сотрудник в отпуске, новые
обращения к нему уходят заместителю — сотруднику с той же должностью, а
если такого нет, с тем же разделом обращений. Студенту бот прямо говорит,
что сотрудник в отпуске и кто ответит; если заместитель не назначен, честно
предупреждает, что обращение подождёт. Без заместителя обращение остаётся
у отсутствующего, а не теряется.

Правило заместителя живёт в одном месте — `repository.replacement_rule()`,
чтобы поштучное и массовое назначение не разошлись.

### Файлы к обращениям

Кнопка «📎 Прикрепить файл»: файл попадает в переписку, сотрудник получает
уведомление и открывает файл в панели. Файлы лежат в папке `attachments`
рядом с базой, одноимённые не затирают друг друга: к имени добавляется
короткий хеш содержимого. Принимаются фото, PDF и документы Word и Excel до
20 МБ, всё остальное отклоняется с понятной причиной.

### Пробелы в данных

Карточка «Пробелы в данных» на главной показывает, что мешает боту работать
полноценно: сотрудники без должности или роли (подменю «Обратная связь» и
адресные обращения не работают), студенты без группы или ФИО, группы без
расписания и люди без согласия. Каждая строка — ссылка на то, где это
дополняется.

## 12. Развёртывание

### Образ

`python:3.12-slim`. Поверх:

- корневой и промежуточный сертификаты НУЦ Минцифры с портала Госуслуг —
  API MAX (`platform-api2.max.ru`) их использует, а в образе их нет. Своя
  сеть или свой набор CA — сборка с `--build-arg INSTALL_RU_CA=0`;
- обратная ссылка `Europe/Yekaterinburg` → `Asia/Yekaterinburg`: в
  `tzdata` 2026c её нет, и без неё время в контейнере тихо остаётся в UTC;
- зависимости ставятся **до** кода: правка бота не заставляет пересобирать
  pip;
- пакеты `handlers/`, `store/` и `web/` копируются отдельными строками
  `COPY`, и их наличие в образе проверяется отдельно от файлов верхнего
  уровня: забытая папка иначе прошла бы проверку молча, а сборка упала бы
  на первом же импорте;
- `RUN python -c "import ... bot"` — проверка импортов на этапе сборки.
  Без неё забытый модуль всплыл бы при первом запуске контейнера, в три
  часа ночи;
- непривилегированный пользователь `app`, uid 10001, владеет только
  `/app/data`.

### Compose

Сервисы `bot` и `tunnel`, именованный том `bot-lpc-data`. Всё изменяемое
живёт в томе: база, бэкапы, кэш PDF, журнал, файл адреса туннеля.

| | |
|---|---|
| Порт | `0.0.0.0:8080:8080` — панель видна с телефона в домашней сети |
| Healthcheck | `/health` каждые 30 с, 3 попытки, стартовая пауза 30 с |
| `stop_grace_period` | 70 с: lifespan ждёт до 60 с фоновых задач перед остановкой, дольше паузы `docker stop` по умолчанию |
| Журнал | `json-file`, 10 МБ × 3 файла |
| Пингвин | `TZ=Europe/Yekaterinburg` |

### Туннель

Быстрый туннель Cloudflare открывает наружу `https://<случайные-слова>
.trycloudflare.com` — этого хватает, чтобы открыть панель снаружи. Сервис
`tunnel` ждёт готовности бота, работает под супервизором и каждые 30 секунд
вылавливает адрес из своего журнала и кладёт в `tunnel_url.txt` в общем томе;
бот его читает. Бинарник берётся из официального образа
`cloudflare/cloudflared`, а не качается с GitHub: проверено из контейнера,
`github.com/.../releases/download` отвечает «connection refused».

`TUNNEL_ENABLED=0` в `.env` выключает туннель без правки compose. Именованный
туннель со своим доменом (постоянный адрес) — через
`CLOUDFLARE_TUNNEL_TOKEN`.

`PUBLIC_URL` в `.env` задаёт публичный адрес для ссылок-приглашений: без
него ссылка получается относительной и открывается только внутри сети, где
видна панель.

### Проверка

```bash
curl http://127.0.0.1:8080/health   # {"ok":true,"platform":"MAX","mode":"polling"}
docker compose logs -f bot
```

### Установка

`install.ps1` делает всё сразу: проверяет Docker, создаёт `.env` с новым
паролем панели, подсказывает, что вписать, собирает образ, запускает
контейнер и дожидается готовности.

```powershell
.\install.ps1            # первый запуск
.\install.ps1 -Start     # применить изменённый .env без пересборки
.\install.ps1 -SkipBuild # перезапустить, ничего не собирая
.\install.ps1 -NoStart   # только проверки и .env
```

## 14. Как проверяется, что тест вообще охраняет

Тест, который не краснеет, когда его свойство ломают, не охраняет ничего.
Поэтому каждое нетривиальное правило проверяется откатом: правило убирается,
тест обязан покраснеть, правило возвращается.

Так были пойманы и починены три вещи, которые иначе тихо уехали бы в следующий
рефакторинг:

- **Разбор аудиторий.** `room_column` считался как «колонка после последней
  группы в файле», то есть всем группам файла доставалась аудитория последней.
  Расхождение с эталоном было в 27 группах из 35.
- **Покрытие статических проверок.** `test_panel_full_names`,
  `test_local_time_display` и `test_button_labels` читали один `webpanel.py`.
  После разбиения панели в `web/` эти проверки обходили фасад в 249 строк
  вместо панели: нарушение, спрятанное в модуле пакета, проходило молча.
  Теперь они смотрят на весь пакет, и подложенная заминка краснеет.
- **Тесты, зависевшие от часов машины.** Пять проверок брали «сейчас»
  отдельно от кода и пользовались `date.today()` вместо `clock.today()`. В
  контейнере машинные часы — это UTC, на пять часов позади, и в полночь «сегодня»
  превращалось во «вчера». Одна из них — `test_today_is_marked_in_the_day_header`
  — проходила только по понедельникам: день недели был зашит в ноль.

Фикстура `frozen_college_clock` подменяет `clock.now` на один фиксированный
момент, и тест вместе с кодом видят одно и то же время. Она не
автоматическая: в тестах, где важны интервалы («5 дней назад», порядок
событий), время должно идти вперёд. Проверено прогоном под семью
замороженными датами — по одной на каждый день недели, обе границы суток и
стык года.

## 15. Соглашения проекта

Эти правила не записаны в коде, но нарушение их стоит дорого.

### Язык

Интерфейс, комментарии, README и сообщения бота — по-русски. Английского в
текстах, которые видит человек, быть не должно. Идентификаторы в коде,
имена файлов, названия таблиц и колонок — латиницей.

### Правка файлов

Файлы правятся временными python-скриптами в
`C:\Users\mafia\AppData\Local\Temp\opencode\`, а не редактором: инструмент
правки ломается на кириллице.

- читать `Path(name).read_text(encoding="utf-8-sig")`;
- писать через `write_bytes(...)` с сохранением BOM;
- **никогда** не писать через `write_text` с байтами — получится `\r\r\n` в
  каждой строке;
- резать большие файлы по границам функций через `ast`, а не по номерам строк;
- сохранять исходные переводы строк: в `webpanel.py` их LF, и если заменить
  на CRLF, diff распухнет вдвое.

### Проверка

```powershell
$env:PYTHONUTF8="1"
cd C:\BOT-LPC
.\.venv\Scripts\python.exe -X utf8 -m pytest -q -m "not panel"   # быстро
.\.venv\Scripts\python.exe -X utf8 -m pytest -q                  # всё
.\.venv\Scripts\python.exe -m ruff check --select F,E9 .
```

Ruff проверяется с `--select F,E9` — этого достаточно, чтобы поймать
неопределённые имена и синтаксис, и он не спорит о форматировании.

### Проверочные скрипты

Временный скрипт не должен писать в локальную `database.db`: переменная
`DB_PATH` модулем не читается, база настраивается через `DATA_DIR`, а
скрипт это обходит. Такое уже случалось — скрипты дописали строки
пользователей в dev-копию. Проверки пишутся только как pytest-тесты через
фикстуру `env` из `tests/conftest.py`, которая поднимает временную базу.

### Одно правило — одно место

Если правило повторяется хотя бы дважды, оно живёт в функции, а
используют её оба места. Примеры: `replacement_rule()` для заместителя в
отпуске, `canonical_group` для кода группы, `person_label` для подписи
человека, `short_label` для обрезки подписи кнопки. Если правило продублировано
в двух файлах, они разойдутся — и разойдутся тихо.

### Никаких выдумок

Данные о колледже берутся с официального сайта. Где сайт отвечает
устаревше или молчит, так и пишется в ответе, с телефонами. Размеры
стипендии не опубликованы — значит, в боте их тоже нет. Сайт колледжа в
трёх местах противоречит сам себе, поэтому в ответах полезнее давать ссылку
на конкретную страницу, чем цифру.

### Тест должен ловить ошибку, а не подтверждать наличие строки

Полезный тест проверяет поведение: «на всех четырёх экранах ФИО целиком»,
а не «в файле есть строка `wb-fio`». Статика по дереву AST допустима, когда
свойство синтаксическое (нет рядов шире двух кнопок, нет `short()` по ФИО) —
AST видит имена и внутри f-строк, чего не видит grep. Регрессия проверяется
откатом: сломанное правило должно ронять тест, иначе тест ничего не
охраняет.

### Тест не должен зависеть от часов машины

Тест, который опирается на «сейчас», обязан брать момент внутри суток,
отсчитанных от начала дня, а не «минус 24 часа»: во втором случае
сравнение «плюс два часа» попадает ровно на полночь, и красный или зелёный
решают часы машины.

### Коммиты

Подробные, по-русски, в `main`, с пушем. Сообщение пишется файлом и
применяется через `git commit -F` — PowerShell ломает кириллицу и кавычки.
В сообщении: что переделано, почему именно так, и что было неочевидно.
